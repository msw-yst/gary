# SV-13: Like for like: the first four-plus-four build against build 14, on the same hardware the same night
Status: finding (part A passed, anchor reproduced; part B measured, its step-0 check not met) · Date: 2026-11-13
Code: in Gary's release commit. Old: the 9 Nov tp4 build with no engine flags (TP-05). New: build 14 with its served and deploy flags (`DS4_XK_QO=1`, `DS4_EG_AHEAD=1`, `DS4_TOPK_MB=1` and the rest of the served environment).

## What and why
- The progress figures in WRITEUP.md §4 compare runs from different days, prompts and harnesses. This run measures the old and new binaries back to back in one harness, on the same box, to give ratios that compare like with like.
- **Part A:** four XTX + four MI50, old tp4 build against build 14. B1 line (64-token prompt, 256 tokens), 4 reps alternating, plus a 2K prompt, 3 reps; drafter loaded but off; one session. An anchor phase re-runs the exact 9 Nov commands.
- **Part B:** one XTX with the experts in host RAM (the EB-03 layout): upstream v0.2.9 (U) and the helper-port binary the first run used (H), against build 14 with (D) and without (D0) its flags.

## Prediction
- A: new / old speed × 1.27 (× 1.20–1.35) at the 64-token prompt, × 1.22 (× 1.17–1.28) at 2K. An earlier hand estimate of × 1.35–1.40 is kept beside it; it compared against a batched one-sequence test, not plain decode.
- B: step 0: the old binaries reproduce the first run's 44.1–46.6 ms a token within ±5 % (about 70 % confident); build 14 × 1.08 (× 0.90–1.30) with flags, × 1.03 (× 0.90–1.25) without. Pre-registered: yes, in the run's proposal, before the run.

## Correctness
- Not an identity run: old and new are expected to differ from the first token (they do).

## Timing
- 13 Nov 20:14, after the hardware change (HW-09). 4 × RX 7900 XTX + 4 × MI50 at 135 W; both binaries on the same cards in alternating order. Part B on XTX #1 alone, 3 reps an arm, alternating.

## Verdict
- **Part A: PASS.** On the same hardware the same night, build 14 decodes 1.325 × faster than the first four-plus-four build after a 64-token prompt and 1.283 × after a 2K prompt, and reads a 2K prompt 1.21 × faster. The short-prompt ratio is inside the predicted × 1.20–1.35 (and just below the hand estimate of × 1.35–1.40); the 2K ratio is just above its range.
- **The anchor reproduces the 9 Nov baseline** within 1 %, so the old numbers were measured right and × 1.3 is a real like-for-like gain.
- **Part B:** with one XTX and the experts in host RAM, build 14 is about where the first binaries were (× 1.02 with flags, × 0.95 without), inside both predicted ranges at their low end. The step-0 check did not hold as written: without their outliers the old binaries ran faster than the first run's 44.1–46.6 ms (U 38.2 ms, H 41.2 ms a token) [I]. In this layout decode is bound by streaming experts from host RAM, which build 14's changes do not address [I].

## Reproduce
- No published run: the code is in the release commit; a scripted public re-run has not been prepared for this card.

## Notes / caveats
- The run's own summary printed "no data" for both parts: the arm containers created the run directories as another user, so the per-run validity files could not be written. Part A was re-validated afterwards on a copy, with the run script's own validity rules applied verbatim (18 of 18 runs valid; summary-a.txt). Part B has not been re-validated that way; its figures are the per-run decode and prompt lines, and every run exited 0.
- Part B has two slow outliers, U rep 2 (13.9 tok/s) and H rep 1 (16.7 tok/s); host-RAM expert streaming (page cache) is suspected, unexplained. With U rep 2 included, D / U would read × 1.33.
- These single-session ratios are drafter-off; served speed with the drafter is in SV-11 and SV-14.
