# QA-18: The native MXFP4 pack on the same agent tasks: it passes where the 2.25-bit pack could not, at hosted's rate; quantisation was a real cause
Status: finding · Date: 2026-11-17
Code: not in the fork's release commit (internal build `nat18-r1`, commit d2a73071: build 17 plus an MXFP4 fix, serving the native MXFP4 pack). Flags: none beyond the native build's serving environment.

## What and why
- QA-17 left two Terminal-Bench 2.1 tasks where speed did not explain the 2.25-bit pack's losses: feal-linear (never found the short solution) and query-optimize (fast, confident wrong answers). QA-11 showed native MXFP4 weights are within the hosted model's own run-to-run noise at the token level.
- Same engine family, same harness (timeout fix from QA-17 in place), only the expert precision changed: does the native pack do these tasks like hosted?

## Prediction
- Pre-registered rule: quantisation is a real cause if native passes ≥ 2 of 3 where the 2.25-bit pack passed 0–1, OR uses ≤ 60 % of the tokens on feal-linear. Pre-registered: yes.

## Correctness
- Not a token-level test. The native pack's token-level distance from hosted: QA-11 (KL 0.0054, top-1 96.0 %).

## Timing
- 16–17 Nov, the 4 XTX + 4 MI50 test machine serving the native MXFP4 pack, one agent at a time. Time limit 4× the task's own (the 2.25-bit and hosted reruns ran at 2×); every native pass also fits inside the 2× limit. The native build decodes slower than the 2.25-bit pack (about 36 effective tok/s on query-optimize, about 38 on regex-chess).
- 3 trials each on feal-linear and query-optimize; 1 on regex-chess (the second cut by plan).

## Verdict
- **Quality was a real cause of the agent-task gap.** On both gap tasks the native pack passes where the 2.25-bit pack could not, at hosted's rate; the pre-registered rule is met on both. On query-optimize a wrong-answer failure became a pass by precision alone: same engine, same harness. On feal-linear native shows hosted's own shape (a short pass or a long miss), and its passes used 18–32K tokens against the 2.25-bit pack's 255–283K.
- This overturns QA-17's "speed, not quantisation" for these two tasks. Speed still explains the rest of QA-17's losses.
- One wrong regex-chess run does not move the verdict; regex-chess stays open, to re-test on a faster native build.
- Decision (17 Nov): the 2.25-bit pack is off the table for agent work (with QA-14).

## Reproduce
- Terminal-Bench 2.1, a native-precision server and a 2.25-bit server, the same harness with a long client timeout (QA-17). The native build's code is not in the published release.

## Notes / caveats
- Three trials a task: small samples. The pre-registered rule was met, but the pass rates themselves have wide intervals.
- The second query-optimize trial shared the server with about 30 unrelated requests (about 26 s each, one at a time); its result (wrong) stands, its time is not clean (REPORTED).
- Native ran with a 4× time limit, the others with 2×. No native pass needed more than the 2× limit.
