# PF-25: Today's build on two XTX: decode a little faster, prompts 13–27 % slower than the old configuration
Status: finding (prompt-path settings are tuned for four XTX + five MI50; the one-XTX arms owed) · Date: 2026-11-20
Code: not in the fork's release commit (internal stack build `stack-r1`, commit baf362a6, against build 17's binary with the 16 Nov native configuration). Flags: none new (the stack environment against the old one).

## What and why
- The prompt-path changes of 19–20 Nov (PF-20 and the stack settings) were tuned on four XTX with MI50 helpers. Do they help or hurt a smaller box? We ran today's build on two XTX (with and without four MI50 helpers), and planned one-XTX arms.

## Prediction
- Two XTX without helpers: disk- and RAM-bound, because the native experts (289 GB) exceed the host's RAM (251 GB) (INFERRED, desk). No numeric bar. Pre-registered: no.

## Correctness
- Not checked (timing comparison only).

## Timing
- 20 Nov, the test machine, native MXFP4 pack, served. Two-XTX tensor parallel with no helpers, and with four MI50 helpers; frozen placement ("F") and live cache ("L"). One start per arm.

## Results

- Two XTX hold 1,130 experts each with 458 MiB free on the lead (MEASURED). Reference, four XTX + five helpers, today: 1u 2K 9.71 ms, 4u 111 tok/s, first token 2K 2.9 s (MEASURED, other runs).
- Two XTX without helpers read prompts at a fixed ~18 s whatever the length (1,657 tokens 18.6 s, 6,543 tokens 18.9 s): the experts are streamed from RAM every read (MEASURED / INFERRED).

## Verdict
- **On two XTX, today's build decodes 4–7 % faster but reads prompts 13–27 % slower than the old configuration.** The prompt-path settings suit the big layout; a smaller box should not take them blindly.
- Two XTX without helpers is ~3.5× slower to decode than the full box (33.8 vs 9.7 ms), as predicted.

The one-XTX arm failed a config gate whose pattern expected the old layer count (a harness bug, no data); it was re-staged separately and is not covered here.
