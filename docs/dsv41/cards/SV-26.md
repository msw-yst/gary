# SV-26: Build 17 under real agent load: 10–15 CPU threads, a 13–68 GB Engram hot set, and prompt re-reading is only about 5 % of server time
Status: finding (a measurement under load; the prompt-reading hypothesis refuted) · Date: 2026-11-15
Code: in the release commit of Gary, our fork of Strata (build 17); the Engram trace used the trace build of ME-12 (not in the published release). Flags: build 17's recommended environment, 4 slots.

## What and why
- HW-11 read the host's memory and CPU from one short sampling session. This run watched build 17 for 3.8 hours while four coding agents worked through a 27-task agent benchmark against it, to size the host for serving (threads, RAM, disk, Engram's page cache) and to see where the agents' wall time goes.
- A second question came from the results: agents finished fewer tasks in time than on the hosted model. Is re-reading prompts (prefill) a large part of the agent wall time, as we guessed (40–50 %)?

## Prediction
- Load monitor: none (a measurement).
- Prompt reading: 40–50 % of agent wall time is prefill (our hypothesis that evening; written in the ledger before the log count, not pre-registered as a run).

## Verdict
- **Size the host for 10–15 threads under four agents, not the 4–5 seen at idle (HW-11).** The ~122 GB of engine memory is the RAM store, a setting; Engram's page cache could be capped near 20–40 GB at a small cost.
- **Prompt re-reading is not the bottleneck: about 5 % of server time, not 40–50 %.** The slot cache reuses 93 % of prompt tokens (SV-15 measured 92 % on build 11). The rest of the agents' wall time is decode under concurrency, plus command execution and the harness.
- **Update (16 Nov):** the 32,768-token thinking cap is our server's default (`DS41_DEFAULT_BUDGET`), applied because our configuration names no budget; it can be overridden per request. The hosted model truncates at 32,768 too (16 of 636 requests), so the cap does not explain the gap (REPORTED). Re-runs with one agent showed the local model also needed more tokens on the same task, so speed alone is not the gap; native 4-bit closed it later (SV-23).
