# QA-21: Quality of the split-KV attention (`DS4_ATTN_SPLIT`): no sign of harm, but top-1 not bounded to the bar; release candidate r2b not shipped
Status: parked (UNRESOLVED under the pre-registered bar; r2b held) · Date: 2026-11-22
Code: not in the release commit of Gary, our fork of Strata (internal branches only: a measurement build for the test; release candidate r2b turns it on by default). Flags: `DS4_ATTN_SPLIT=1` (`=0` turns it off in r2b); `DS4_ATTN_MERGE=2` in this test.

## What and why
- `DS4_ATTN_SPLIT` splits the attention over the key/value cache into chunks so that more of the XTX's compute units work at once. In decode timing it took −1.06 to −1.13 ms off a token, and stacked with the BF16 matvec (FG-20) to −2.37 ms (MEASURED, 4,000-token untraced decode runs at 2K, FG-33). It is not bit-identical: the chunks' partial sums are added in a different order. So it needs a quality pass before it can ship.
- Release candidate r2b = r2a (the shipping stack build) + `DS4_ATTN_SPLIT` on by default.

## Prediction
- Bar (pre-registered, as QA-20): dKL ≤ +0.001 AND dTOP1 ≥ −0.3 pp against the control; PASS only when the whole 95 % interval is inside. The split arm must also show it engaged (launch counts), or the run is NO DATA.

## Correctness
- This card is the correctness test. Controls (split off, at either end of the run) identical: KL 0.00571, top-1 95.86 % both (MEASURED).
- Engagement: 248,640 split launches in the split arm (160 a window over 1,554 windows), 0 in the controls (MEASURED).

## Timing
- 21 Nov: the first attempt (single-token steps) on the test machine. 21–22 Nov: the re-run on the verify-window path, QA-11's 12 prompts, 2,900 positions, teacher-forced, each prompt scored with windows of 1, 2, 3 or 4 rows (3 prompts each), the drafter's verify windows. Quality only.

## Verdict
- **No sign that the split hurts quality**: KL is, if anything, slightly better, and top-1 changes are balanced (30 lost, 32 gained). But 2,900 positions cannot bound top-1 to 0.3 pp, so by the pre-registered rule the result is UNRESOLVED, and r2b's release gate, which needs a PASS here, cannot pass it.
- Decision (21 Nov): release candidate r2a goes first; r2b was held even before this test, because the split changes the drafter's 2–5-row verify windows as well as single-token steps.
- Decision (22 Nov): r2b deprioritised. A desk study predicts a served gain of only −0.15 to −0.35 ms a token, and none at block-6 windows, where the split does not engage (INFERRED). A larger quality re-run only if a served gain is shown to be worth it.

## Reproduce
- Not reproducible from the release: r2b is not published. The quality method is `validation/hostlp/` (QA-11).

## Notes / caveats
- The re-run used `DS4_ATTN_MERGE=2`, because the `=3` load check refused to start with the split on; the second r2b candidate skips that check when the split is on.
- One run an arm; controls identical.
