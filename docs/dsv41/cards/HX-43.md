# HX-43: Two XTX with 0 to 5 MI50 helpers on the native build: decode scales with every MI50 (×1.68 from none to five)
Status: finding · Date: 2026-11-20
Code: not in the release commit of Gary, our fork of Strata (internal branch only: the stack build, with `DS4_MXW=3`, HX-36). Flags: none new; the XTX and helper sets are launch options.

## What and why
- How does a smaller box, two XTX, scale with MI50 helpers on today's engine? With the native MXFP4 pack, two XTX hold only 1,130 experts each and the rest sit in host RAM (about 289 GB of experts against 251 GB of RAM with no helpers, so partly disk-bound; REPORTED from the desk check). Each MI50 takes about 1,700 experts off the CPU lane.
- Nested helper sets: H0 (no MI50); H1 to H4 add the four production MI50s one at a time; H5 adds MI50 #5 (clock pinned `high`).

## Prediction
- None recorded: a scaling sweep. Pre-registered: no (validity gates only).

## Correctness
- Not an identity test: each helper set places experts differently. All six arms VALID by the run's gates (MEASURED). Cache moves inside timed cells could not be checked: no swap line in the logs, so "moves unverified" on every arm (MEASURED).

## Timing
- 20 Nov 20:11 (H0, H1) and 22:24 (H2–H5, a re-run without arm time caps after the first attempt lost H2 / H3 to a 1,500 s cap). Two XTX in tensor parallel, the stack build live as served (no freeze, no deterministic cache), 131K context, drafter on. Cells: one user at 2K and 8K (decode tok/s), four users (total tok/s), first token at 2K and 8K (two reps each), prompt tok/s.

## Verdict
- **Decode scales with every MI50**, because each one moves about 1,700 experts from host RAM to GPU memory. MI50 #5 still adds 4.5 % (2K) and 6.1 % (8K) at one user.
- Four-user throughput flattens from four to five MI50s (64.4 → 64.5 tok/s).
- First token flattens at about 17–20 s from two MI50s on (once no expert is read from disk). The 2K outliers (H1, H3 rep 1) are cold-read stalls; quote rep 2.

## Reproduce
- Not reproducible from the published code: the stack build is not in the public commits. `tools/dsv41/bench-perms.sh` measures the same kind of grid with the release build ([benchmarking-gpu-permutations.md](../benchmarking-gpu-permutations.md), the 2.25-bit pack).

## Notes / caveats
- One run a cell (two for first token). Live cache, no page-cache drop between arms in the re-run.
- The 2 XTX + 1 MI50 prompt stall echoes the erratic 2 × 1 prompt reads in the earlier permutation grid (TP-07, benchmarking-gpu-permutations.md) [I].
- A run the same afternoon (2 XTX + 4 MI50, today's build against the 16 Nov build) found today's prompt path 13–27 % slower to first token on two XTX: the prompt-path changes were tuned for 4 XTX + 5 MI50 (MEASURED, PF-25). Its one-XTX arm had no data (a gate pattern bug).
