# NX-09: B6 multi-row matvecs under TSUM
Status: kept (opt-in; proposed as the gfx1100 default) · Date: 2026-11-21
Code: in the fork's `flashnext-amd` commits. Flags: `STRATA_B6_MMVQ_ROWS=1` (with `STRATA_TSUM=1`); `STRATA_B6_MMVQ_MIN` (default 7 columns under TSUM).

## What and why
- At 8 rows every Q6_K multi-column matvec ran at 227-271 GB/s against 518-612 at 4 rows (2.2-2.4x the time): the cause of the convex 4 -> 8 user window growth. The existing B6 kernel was exact and saved 2.4 ms (tp2) / 3.9 ms (one card) per 8-row window, but `STRATA_TSUM=1`, which the served environment sets, switched B6 off, and TSUM itself is worth 0.8-0.9 ms.
- The B6 kernel now has TSUM's epilogue (bitwise the same sums) and, under TSUM, takes calls of 7 or more columns.

## Prediction
- About -3.2 ms (tp2) / -4.8 ms (one card) per 8-row window, +7 % / +8 % at 8 users (ESTIMATE from the timing study).
- Pre-registered: yes (the timing study's estimate).

## Correctness
- Kernel bench: bitwise equal to the default and to single-column calls in every case. Servers: reference hashes unchanged, batched == solo 8/8 (MEASURED).

## Timing
- Hardware: 2 × RX 7900 XTX 24 GB, 4 × Instinct MI50 16 GB (135 W cap), EPYC 7642 (48 cores), 256 GB DDR4-2666.
- Software: Strata v0.2.9 plus this fork's changes on ROCm 7.2 (the runtime in Strata's ROCm image). Kernel version: not captured in the published extracts.
- Workload: 8 prompts × 384 tokens, temperature 0; one server at a time, two alternating runs per arm.

## Verdict
- Kept, inside the prediction for one card and slightly under it for tp2. In every recommended environment.

## Reproduce
- Any layout at 8 users with and without `STRATA_B6_MMVQ_ROWS=1`.

## Notes / caveats
- At 4-6 columns B6 was neutral except the tp2 gate half (up to 1.35x slower), hence the 7-column minimum.
- 8-row Q6_K calls still reach only 300-450 GB/s against 450-600 at 4 rows: ~1-1.5 ms per 8-row window per card left, mostly the lm head.
- Tried and dropped: one warp per row group running the exact layout's four partial loops in sequence (exact, 1.1-3x slower).
- Absolute numbers come from a private prompt set (not published); ratios between arms of the same run are the comparable quantity.

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output), ESTIMATE (our arithmetic) or INFERRED (our own reading).
