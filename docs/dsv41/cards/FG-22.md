# FG-22: The CPU lane on the native pack: a quarter of a decode step, last to finish on 70 % of layers, concentrated in eight layers
Status: finding · Date: 2026-11-18 (per-layer trace 2026-11-19)
Code: not in the release commit of Gary, our fork of Strata (the native build is internal). Measurement: engine counters, a lane-skip timing oracle, and a kernel trace read offline.

## What and why
- On native, 12,688 experts (238.9 GB) do not fit on the GPUs and run on the CPU lane, from a RAM store or the model files (MEASURED, placement lines). FG-21 found the lead waiting about 8 ms a verify step for them. This card measures the ceiling of removing that wait, and where in the model it lands.

## Prediction
- None as numbers; diagnostics.

## Correctness
- The lane-skip arm's output is invalid by design (a timing bound). The kernel trace's launch gaps are not production values (graph capture off for tracing); kernel durations are (MEASURED caveat from the run).

## Timing
- 18–19 Nov, the test machine: 4 × RX 7900 XTX (tensor-parallel 4) + 4 × MI50 helpers; native MXFP4 pack, internal native build, one user. Ceiling run: 4 repeats, drift × 1.009. Trace: 1,098,890 kernels, analysed offline (35 of 40 steps usable, coverage 0.974).

## Results
| measure | value | label |
|---|---|---|
| verify step, normal / CPU lane skipped | 44.79 / about 33.4 ms | MEASURED |
| ceiling of emptying the CPU lane | **11.32 ms a step (25 %; SD 4.72, n 4)**, up to about 34 % faster decode | MEASURED / INFERRED |
| lane time a token (counters) | compute 1.0 ms, store wait 1.0–1.4 ms, lane busy 2.2–2.7 ms; sync about 0 | MEASURED |
| who finishes last in a joined layer | **the CPU lane on 70 % of layers**; each MI50 3.5–9.4 %; the XTXs 6.1 % | MEASURED (offline trace analysis) |
| lead's wait on the lane | about 8.0–9.4 ms a step untraced (11.5 traced); spiky (SD 12.0 ms) | MEASURED (offline trace analysis) |
| where it lands | layer 19 (1.0 ms a step), then layers 4, 18, 39, 21, 25, 34, 28 (0.55–0.67 ms each); layers 2, 5, 11, 12, 16, 23, 36 about 0 | MEASURED (offline trace analysis) |
| decode picks on the CPU lane | 3.85 %, spread flat over 7,964 experts (half the picks need 1,682 experts) | REPORTED (an expert-heat count read at the time) |

## Verdict
- **The CPU lane is the native decode bottleneck:** up to a quarter of a step, and the last finisher on 70 % of layers. About eight hot layers carry half of its cost.
- **Levers, by evidence:** put the hot layers' CPU experts on GPUs (per-layer, lane-aware placement), or give the GPUs room for all experts (a fifth MI50, HW-14; mixed precision, QA-12, QA-13). Making the lane itself faster has little room (FG-23).

## Reproduce
- No published run: the native build is not in a release.

## Notes / caveats
- The trace first failed to finish (the engine ignored the stop signal and the tracer never flushed); a second capture with a clean stop worked. Its in-package analysis then said NO DATA only because the new fifth MI50 was visible as an extra device; the offline analysis drops idle devices.
- The lane-skip ceiling has a wide spread (SD 4.72 ms on 11.32) at n = 4.

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output) or INFERRED (our own reading).
