# QA-11: The 2.25-bit model against the hosted model's own logprobs (HOSTLP): the quantisation is the gap; native MXFP4 closes 88 % of it
Status: finding · Date: 2026-11-16
Code: build 17, in the fork's release commit (release 3), and upstream Strata v0.2.9. Tools: `validation/hostlp/` (fetch, token mapping, scorer, the Strata pack tokenizer adapter) on top of `validation/engine-parity/`.

## What and why
- QA-10 showed our engine computes what upstream computes. Agent tasks still scored lower locally than on a hosted DeepSeek V4.1 Flash API. This asks whether our quantised model's next-token distributions differ from the hosted model's, token by token, and by how much compared with the difference between two engines.
- Reference: the hosted API's greedy (temperature 0) 256-token continuations of the same 12 prompts as QA-10, with its top-20 logprobs at every step. Each of our arms is teacher-forced along those exact tokens (mapped by bytes into our tokenizer).

## Prediction
- Pre-registered reading: QUANT COST SHOWN if both Strata arms sit more than 3× further from hosted than from each other; ENGINE COST SHOWN if they differ from each other by more than that; otherwise NO MEASURABLE DIFFERENCE. For the native-weights run: ≥ 70 % of the gap closed means the hosted API serves (effectively) the original weights; < 40 % means precision is not the lever.

## Correctness
- Hosted token sequences mapped into our ids byte for byte: every prompt accepted; prompt token counts matched the hosted API's reported counts. Hosted top-20 entries mapped by bytes as well (MEASURED).
- A second analyst re-scored V and P1 with independent code: top-1 0.903 for both, the same verdict; the KL values differ by formula (0.047 against 0.044) (REPORTED).

## Timing
- 16 Nov. Hosted fetch cost EUR 0.07 (a repeat fetch EUR 0.09). The 2.25-bit arms ran on one RX 7900 XTX with host-RAM experts (as QA-10); the native-MXFP4 arm and its layout control on the 4 XTX + 4 MI50 test machine. Not a timing run.

## Verdict
- **QUANT COST SHOWN (pre-registered):** both Strata engines are about 10× further from hosted (0.043–0.044 nats) than they are from each other or from llama.cpp (about 0.004), and agree with each other where they disagree with hosted (disagreement with hosted 9.7 % against 2.5 % between engines). The engine is cleared; the 2.25-bit weights are the gap.
- **Native MXFP4 closes 88 % of it** ((0.0438 − 0.0054) / 0.0438), past the pre-registered 70 %: the hosted API serves effectively the original weights. The layout control rules out the 8-card layout as the cause.
- **Native MXFP4 is within the hosted API's own run-to-run noise** (0.0053 against hosted-to-hosted 0.0190 on the same positions). There is no quality headroom beyond native weights; the 2.25-bit build sits at about 2× the hosted noise.

## Reproduce
- `validation/hostlp/README.md`. You need access to a hosted API that returns top-k logprobs, and your own prompts.

## Notes / caveats
- llama.cpp was not forced along the hosted tokens (its server has no forced-scoring path); declared before scoring.
- The KL is over hosted's top-20 plus a rest bucket: an approximation, not a bound. Different formulas give different absolute values (see Correctness); the ratios and verdicts agree.
- The native-MXFP4 and hosted-repeat rows are REPORTED from the scored summaries at the time; their per-position files are not part of `data/`.
- Prompts, hosted answers and all token ids are private and are not published; the tools print numbers only.

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output) or INFERRED (our own reading).

Sources: `data/cards/QA-11/` (SHA256SUMS, hostlp-summary.txt); sanitised copies, checked by `SHA256SUMS`. Originals are held privately.
