# PF-21: The short-prompt cutoff re-measured on the new prompt path: 256 is 13 % faster on average, with one cell 0.18 s slower; adopted by operator call
Status: kept (cutoff 256 adopted for the next release configuration by operator decision; by its own pre-registered bar the run said "keep 512") · Date: 2026-11-20
Code: not in the release commit of Gary, our fork of Strata (internal branch only). Flags: `DS4_CHUNK_MIN` = `DS4_PICK_MIN` = 256 (branch-only; 512 is the native build's default).

## What and why
- PF-17 found the crossover between the windowed short-prompt path and the chunked path at about 1,190 tokens of code on the old prompt path. Since then the chunked path became 4.6× faster at 2K (PF-20) and a fifth helper joined (HX-37), so the crossover had to move down.
- This run measures cutoffs 0 (every read chunked), 256, 512 (the default) and 1,000 on the new base.

## Prediction
- Pre-registered rule: a cutoff replaces 512 only if its geometric-mean first token is lower **and no cell is slower** beyond noise.

## Correctness
- Every arm CONFIG ok; drift × 0.983–1.000 (MEASURED). Both paths are the engine's existing paths; no new code.

## Timing
- 20 Nov, the test machine: 4 × RX 7900 XTX (tensor-parallel 4) and 5 × MI50 32 GB helpers (HX-37); native MXFP4 pack with PF-20's setup. 28 first-token cells a start, 100–1,500 new tokens: code turns after an 8K and a 3K primed context, cold filler and cold code. Order K0a K256a Ba K1000a K1000b Bb K256b K0b (B = 512).

## Verdict
- **By its pre-registered rule: keep 512.** 256 failed the no-slower-cell bar on one cell.
- **Adopted anyway: 256, by operator decision** ("go with the fastest option"), accepting the 0.18 s loss on short filler prompts for a 13 % lower first token on average.
- The crossover of PF-17 (about 1,190 tokens) has moved well below 1,000 on the new path: 1,000 now loses up to 4.9 s on 600–800-token code turns.

- No published run: the native build is not in a release.
