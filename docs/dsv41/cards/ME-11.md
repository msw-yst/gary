# ME-11: Builds pinned to spare cores may run during timing runs
Status: method · Date: 2026-11-13
Code: not applicable. Flags: host scheduling only.

## What and why
- ME-04 forbade builds during timing runs. That rule cost queue time. This run measured whether a real `-j4` engine build, pinned to two cores and their SMT siblings at the lowest CPU and I/O priority, disturbs a timing run.

## Prediction
- Pass if the arm with the build lies inside the spread of two quiet arms before and after it. Pre-registered: yes, in the run script.

## Correctness
- Not applicable.

## Timing
- 13 Nov 06:01, pre-incident hardware, build 13s served env, one user, a 9-request probe (~8K-token prompts): quiet / with build / quiet.

## Verdict
- **No measurable contention:** the build arm sits inside the drift between the two quiet arms. From now on, builds pinned to the spare cores at idle priority may run during timing runs.
- Caveat: the overlap was partial (the build finished just before its arm ended, about 3 minutes). A longer full-overlap check is cheap to add if a later timing looks off.
