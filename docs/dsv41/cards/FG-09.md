# FG-09: The Engram chain one layer ahead on a side stream (`DS4_EG_AHEAD`)
Status: kept (build 13; served) · Date: 2026-11-12
Code: in the fork's release commit. Flags: `DS4_EG_AHEAD=1` (default off; on in the served environment from build 13).

## What and why
- The two Engram layers (1 and 14) read table rows from host memory, copy them to the XTX, dequantise them and run a GEMV. With build 12's split (`DS4_EG_SPLIT`, SV-09) the GEMV is cheap, but the copy and dequantise still sit on the token's path.
- This flag starts the Engram chain for a layer one layer early, on a second stream, so the copy and dequantise overlap the layer before. The rows depend only on the tokens, so they can be fetched before the layer needs them.

## Prediction
- B1 (single session, drafter off) −0.12 to −0.02 ms a token (central −0.07); production (served mix) −0.14 to −0.02 ms a generated token (central −0.07). Pre-registered: yes, in the run's prereg, before the run.

## Correctness
- 4 identity lines IDENTICAL: unset vs the base build; on vs off on decode, drafter decode and batch test (MEASURED). Every on process printed its engagement line (2,496 prefetches taken in each production rep).
- Exact by construction: the same rows, the same kernels, only issued earlier on another stream.

## Timing
- Hardware: 4 × RX 7900 XTX (XTX #1–3 Gen4 x16, XTX #4 Gen4 x8) + 4 × MI50 32 GB at 135 W (Gen4 x4 each). XTX at minimum power cap with −50 mV. MI50 DPM `high` (CP-03).
- Software: ROCm 7.14 on Linux; Strata v0.2.9 plus this fork's changes (build 12 with the prompt-helper port, "build 12pf").
- OFF / ON / placebo, 6 reps each, interleaved. B1: 64-token prompt, 256 tokens, drafter off. Production: the served mix, sampled, matched by request position (8 of 8).

## Verdict
- **Production −0.111 ms a generated token (−1.1 %), inside the prediction, exact.** Kept, and on in the served environment from build 13.
- B1 is not separable: one off rep at 13.732 ms pulled the off mean up and the placebo moved by −0.092, beyond its 0.05 bound. The B1 gain is likely real but this run cannot show it.
- Unlike most single-row savings (FG-08), this one also pays in serving, because it removes whole copy work from every token, not one launch on the one-row path [I].
