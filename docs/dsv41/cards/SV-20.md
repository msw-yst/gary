# SV-20: The native pack as served today against our 16 Nov benchmark: one user 82.5 → 107.5 tok/s, eight users 127 → 151, 2K first token 20.2 → 3.6 s
Status: finding · Date: 2026-11-20
Code: not in the release commit of Gary, our fork of Strata (internal branch only). "As served" = STACK's configuration (SV-18) with a live expert cache; no test-mode switches.

## What and why
- On 16 Nov we benchmarked the native MXFP4 pack on the then-current build. Since then the prompt path, the helpers and the placement have all changed (PF-15 to PF-20, HX-37, SV-18).
- Two questions: does the 16 Nov baseline still reproduce on today's box (B2: the 16 Nov build and settings re-run today), and what does today's configuration give on the same cells as it is actually served (T0, live cache)? A third arm (TF) runs today's configuration in the locked placement mode STACK was measured in.

## Prediction
- Pre-registered: B2 reproduces each 16 Nov cell within its band; T0 no more than 10 % slower than TF on any cell (otherwise the served configuration is blocked).

## Correctness
- Speed-only; every arm CONFIG ok (MEASURED). A first attempt at T was invalid: it ran the placement test mode without its freeze, so every live expert move was waited for synchronously, and its numbers are not used (ME-16).

## Timing
- 20 Nov, the test machine: 4 × RX 7900 XTX (tensor-parallel 4) and MI50 helpers at 135 W (five in T0 / TF; the 16 Nov arm's own layout in B2); one EPYC Zen 2 16-core host, DDR4 at 2933. Native MXFP4 pack; the 16 Nov cells (one user at 2K and 8K, four and eight users, first token at 2K / 8K / 32K).

## Verdict
- **The 16 Nov baseline holds for one user, four users and the 2K first token.** The eight-user figure did not reproduce (−7 % today), so the eight-user gain is quoted as × 1.19 against the published figure, the more conservative of the two; × 1.28 is against today's re-run.
- **As served today, the native pack runs one user at 107.5 tok/s, four users at 119, eight at 151, with first tokens of 3.6 s at 2K, 7.6 s at 8K and 26.4 s at 32K.**
- **Live is faster than locked on decode (+6–9 % on every cell) and slower on the first token** (2K +0.68 s, × 1.23; 8K +0.49 s; 32K +0.6 s). The pre-registered 10 % gate trips on one cell, the 2K first token. A likely cause and a fix are on ME-16; the fix is not yet tested.
- STACK's locked-mode numbers (SV-18) therefore understate served decode and overstate the served 2K first token by about 0.7 s.

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output) or INFERRED (our own reading).
