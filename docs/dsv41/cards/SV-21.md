# SV-21: Build 16's five changes switched off one at a time: each decode change keeps its gain, and the cache fix is what makes batched output match solo
Status: finding (the ablation behind SV-16's single-process row; adds the drafter, batch, long-prompt and batched-identity arms) · Date: 2026-11-14
Code: in the release commit of Gary, our fork of Strata (build 16). Flags: `DS4_XK_QA`, `DS4_IXS_DISPATCH`, `DS4_ATTN_MERGE` (`=3` against `=2`), `DS4_PF_HELPER_MAXP`, `DS4_EC_FIX`, each unset in turn from build 16's recommended environment.

## What and why
- Build 16 added five switches to build 15 (SV-16). Served, one user got slower on the same day (SV-16's A/B), while in one process the five together were faster. This run asks what each switch is worth inside the full build, by switching one off at a time, and whether any of them changes the output.
- SV-16 and FG-16 already carry the all-on / all-off decode figures and the three decode switches' per-switch costs. This card adds the rest of the run: drafter-on decode, an 8-row batch step, a 32K prompt, the batched-against-solo check per arm, and the log reading that reconciled it with an earlier identity run.

## Prediction
- Each change costs about its own measured gain when switched off (FG-12, FG-16, PF-13). Pre-registered: yes, in the run's plan.

## Correctness
- **Batched output against solo: 8 of 8 identical with `DS4_EC_FIX=1`; 0 of 8 with it off** (the arm without the fix and the all-off arm; the batch test's exit code 3) (MEASURED).
- An earlier identity run on build 15 had found batched = solo 8 of 8 without the fix. Reading both runs' engine logs: both used device-direct MI50 windows with four helpers, but only this run's arm logged the expert cache's RAM parts made resident at load; the earlier arm had no expert-cache line, so its cache was effectively off (MEASURED log lines; the reading is INFERRED, not a dedicated A/B). That fits HX-28: picks are summed twice only with the expert cache **and** device-direct helpers on.

## Timing
- 14 Nov (the run started 11:06 UTC with the GPU grid; the ablation phase ended about 14:40), 4 × RX 7900 XTX + 4 × MI50 at 135 W, the 2.25-bit pack. Single process, one run an arm; the all-on arm was run twice to give the noise (0.04 ms a token).

## Verdict
- **Each of the three decode changes keeps its gain inside the full build (+0.15 to +0.17 ms each when removed), and together they are worth 0.44 ms a token.** The prediction held for all three (their stand-alone gains were 0.13–0.21 ms) (INFERRED comparison).
- **`DS4_EC_FIX` costs no single-process decode speed and is what makes batched output equal solo output** in this harness: more evidence for HX-28.
- Served, build 16 was still slower than build 15 for one user on the same day (SV-16). That loss is the cache fix stopping the cache's promotion, which a single process with no prompt traffic cannot show (HX-29).

## Reproduce

- One run an arm; the noise comes from one repeat of the all-on arm.
- The same-day served A/B of build 15 against build 16 (one user +5.3 % / +8.7 % a token, 32K first token −18.3 %, identity PASS) is in SV-16 and is not repeated here.
