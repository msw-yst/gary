# DR-09: Tree speculation for the drafter: a desk model, and a counting build (`DS4_TREE_STATS`)
Status: dropped (the counting run closed the idea: h2 0.337, under the 0.35 close line) · Date: 2026-11-13 (result 2026-11-14)
Code: not in the fork's release commit (internal branch only). Flags: `DS4_TREE_STATS=1` (measurement only; default off, never served).

## What and why
- Today the drafter proposes one chain and the trunk verifies it in one window. Tree speculation would also verify the drafter's second choice at position 1 (and perhaps 2) in the same window, and keep the longest path the trunk agrees with.
- The desk study asked when that pays on this engine. Drafting a tree is almost free here (the drafter's rows do not depend on earlier drafts, only its small Markov bias does), but verifying is not: each extra verify row costs about 2.66–2.70 ms (DR-06 addendum), because it brings its own routed experts and helper picks.

## Prediction
- The model (relative, not absolute; fitted to the depth sweep of DR-08): a lone sibling at position 1 breaks even only if h2 = P(the trunk's token is the drafter's second choice, given the first was rejected) exceeds **1.01 at full row price** (impossible) or **0.50 at half price**. Predicted gain of a tree: central 0 %, range −7 to +2 %. Pre-registered: yes, in the study note.
- Reading rule for the counting run: h2 ≥ 0.50 → measure the sibling row's real price next; 0.35–0.50 → park; < 0.35 → close the idea.

## Correctness
- A full tree build would need tree attention ranges, side buffers for sibling KV rows, per-branch compressor and indexer state, Engram hashing by ancestor path, path-wise drafter seeding and a multi-candidate sampled verify rule; the study argues greedy exactness and distribution exactness for that design. Not built.
- The counting build: one source file +103 lines behind `DS4_TREE_STATS=1`; the machine code of all 2,607 kernels is identical to build 15's and none was added (REPORTED from the build notes). It only counts rejections at position 1 and how often the trunk's token was the drafter's second choice.

## Timing
- Desk study, 13 Nov. Counting run 14 Nov 01:25 on a later build (not in this release), served mix sampled and greedy, flag on against off and against build 15.

## Verdict
- **Not viable at today's verify-row price unless h2 ≥ 0.5 and sibling rows cost half a chain row.**
- **Counting run: CLOSE.** On the served (sampled) mix the drafter's second choice was the trunk's token in 0.337 of first-draft rejections, under the 0.35 close line; greedy 0.419 would only have parked it. A second branch would rescue about 1 in 3 first-draft misses, about 11 % of rounds [I], not worth a tree verify. Tree speculation is closed.
