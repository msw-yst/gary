# QA-20: 8-bit attention weights (BF16 → Q8_0) on the native MXFP4 pack: KL within the bar, top-1 unresolved; not adopted
Status: parked (unresolved under the pre-registered bar; 8-bit attention not adopted) · Date: 2026-11-21
Code: not in the release commit of Gary, our fork of Strata (internal branch only: the stack build, loading a Q8_0 copy of the dense matrices). Flags: none (a pack change).

## What and why
- On the native MXFP4 pack the attention, shared-expert, indexer, compressor and Engram matrices are BF16. Storing them as Q8_0 frees 1.2–2.1 GB on each XTX, room for 211–402 more experts in VRAM each, so fewer experts on the CPU lane.
- Three packs: **a8** (all 621 such matrices as Q8_0, −2.13 GB an XTX); **a8p** (the attention projections only, 480 matrices, −1.45 GB); **a8pe** (a8p but layers 0–2 and 37–39 kept BF16, weights 4.12 GB, +211 experts an XTX).

## Prediction
- Bar (pre-registered, both runs): dKL ≤ +0.001 AND dTOP1 ≥ −0.3 pp against the native control. In the 12-prompt run PASS / FAIL only when the whole 95 % interval is inside / beyond the bar; otherwise UNRESOLVED. Going in, a clear regression was expected.

## Correctness
- Controls bit-reproducible: two control runs at either end of the 12-prompt run differ at 0 of 2,900 positions (MEASURED).
- Control against the 16 Nov native score: dKL −0.00010 [−0.00058, +0.00038] (MEASURED).

## Timing
- 21 Nov, the test machine, the native MXFP4 pack. Screen: 4 prompts, 1,024 positions. Full run: QA-11's 12 prompts, 2,900 positions, paired two-level bootstrap (prompts, then positions; 10,000 resamples). Quality only; speed not run.

## Verdict
- **Not the clear regression expected, and not proven safe.** KL: the whole interval is inside the bar for all three packs. Top-1: every interval straddles −0.3 pp, so all three are UNRESOLVED by rule (point estimates −0.14 to −0.41 pp).
- a8 (every matrix) shows a small real loss in NLL (interval excludes 0). a8pe, which keeps the first and last three layers BF16, is the best and closest to native.
- The 4-prompt screen's FAIL was within about one standard error and non-monotone (converting more matrices scored better), so the screen could not separate a loss from noise; the 12-prompt run was the check.
- Separating −0.14 pp from −0.3 pp needs more reference prompts than the 12 we have hosted top-20 logprobs for. 8-bit attention is not adopted.

## Reproduce
- Not reproducible from the release: the Q8_0 dense packs and their build tool are internal. The quality method is `validation/hostlp/` (QA-11).

## Notes / caveats
- One run an arm; the controls show the scoring itself is exact.
- Per length bin and per prompt the top-1 intervals are wider still (± 1–4 pp); no bin shows a clear loss.
- The expert room figures are from the load logs; the speed gain from the extra experts was not measured.
