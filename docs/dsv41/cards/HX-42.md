# HX-42: Pinning MI50 #5's clock `high`: no help, probably 2–3 % slower at 2K; the all-MI50 re-test has no data
Status: dropped (MI50 #5 recommended at `auto`; not proven either way) · Date: 2026-11-21
Code: no engine change (the launch wrapper's MI50 clock pin extended to MI50 #5); runs on the stack build (internal branch only) with `DS4_MXW=3` (HX-36). Flags: none.

## What and why
- MI50 #5 is the fifth helper on the native build since 20 Nov (qualification in HW-14, the fifth helper's gain in HX-37).
- In a trace on 20 Nov, MI50 #5 was the last helper to finish in 49 % of the layers that finished late, about 0.30 ms a token (p99 242 µs against 135–167 µs on the other MI50s) (REPORTED). It ran at DPM `auto` while the four production MI50s run pinned at `high` (CP-03, ME-09).
- The question: does pinning MI50 #5 `high` too make served decode faster?

## Prediction
- Pin A/B: a 95 % interval on one-user decode that excludes 1 to call a difference. Pre-registered: yes.

## Correctness
- Not an output change (clock setting only). Not checked as identity.

## Timing
- 21 Nov, the test machine (4 XTX + 5 MI50), native MXFP4 pack, drafter on, live cache as served (ME-16).
- Full-box run (00:35): all five MI50s pinned `high`, compared with the 20 Nov served benchmark (SV-20).
- Pin A/B (03:56): four servers in order `high` / `auto` / `auto` / `high` for MI50 #5 only; 6 scored reps a cell.
- All-MI50 pin A/B (14:43): `high` against no pin, ABBAABBA.

## Verdict
- **Pinning MI50 #5 `high` does not help.** Every pair points the same way (`high` 2.5–3.5 % slower at 2K, about 1 % at 8K), but the 95 % interval just reaches 1, so a loss is not proven.
- The pin mostly raises MI50 #5's memory clock; the core clock stays about 925 MHz. Why it would be slower is not known: a shared power or thermal budget, or a PCIe effect, are candidates, not shown (INFERRED).
- Recommendation (21 Nov): keep MI50 #5 at `auto`. The recommendation was not applied: the release gate for r2a (SV-25) ran all five MI50s pinned `high`, MI50 #5 included, in every server (MEASURED from its pin records). A decision to revert or keep the pin is open.
- Whether the four production MI50s still gain from their own pin (CP-03, measured once each way on 10 Nov on an older build) is open: the re-test has no data.

## Reproduce
- Serve the native build with MI50 #5 at `auto` and at `high` (`power_dpm_force_performance_level`), alternating servers; compare one-user decode.

## Notes / caveats
- The full-box run compares with a run the day before, not within one session; the pin A/B was set up to settle that.
