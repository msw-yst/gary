# SV-28: The server's chat-request conversion now matches DeepSeek's reference encoder: 12 real differences → 0, and agent conversations keep their cached prefix on every turn
Status: done (server-only fix; not deployed) · Date: 2026-11-22
Code: not in the fork's release commit (internal build `tmplfix-r1`, commit 51927806, on top of `prodprep-r1`; carried into the second release candidate, internal build `stack-r2a-rc2`, commit 41278574). Flags: none (applies to the DeepSeek V4.1 family only; other model families convert as before).

## What and why
- The server turns OpenAI and Anthropic chat requests into the model's prompt. If that differs from what DeepSeek's own encoder produces, the model sees prompts it was not trained on, and a conversation's earlier prompt may stop being an exact prefix of the next one, which costs the prompt-reuse cache (SV-15).
- A comparison against DeepSeek's reference encoder (the model's official `encoding` code, pinned) found 12 real differences in 219 cases, from 4 causes, all in the server's request conversion, not in the chat template: (1) a mid-conversation system or developer message was sent as a user turn, where V4.1 has its own system turn; (2) multi-part text was joined with nothing instead of a blank line; (3) an empty assistant turn was dropped and the user turns either side merged; (4) the `task` field (`<｜action｜>` and the other task tokens) was dropped. A fifth, hidden behind (1): tools on a mid-conversation system message were dropped.

## Prediction
- None written. Bar: 0 real differences, and no case that already matched changes.

- All four earlier prefix failures came from the dropped empty assistant turn: one turn later the turn vanished and the user turns merged, so the cache checkpoint after it was lost (MEASURED).

## Verdict
- **The server now builds the prompts DeepSeek's encoder builds, for every request shape in the corpus.** The chat template was never wrong; every difference was in the server's request conversion.
- **Agent conversations keep an exact cached prefix on every turn** (40 of 40 against 36 of 40). The speed effect is small and not measured: a conversation that gets an empty assistant reply no longer loses its checkpoint at that turn (INFERRED).
- **Left to decide (22 Nov):** whether to keep empty assistant turns for DeepSeek, as the fix does (an earlier server change dropped them for quality; dropping them breaks the prefix again); and whether to accept one cache miss per conversation at upgrade: any history with a multi-part system prompt, a mid-conversation system message or an empty turn renders differently on the new server once. A coding-agent client that sends its system prompt as a list of blocks (about 22K tokens with its tools) misses once after the upgrade.

## Reproduce
- The comparison harness and corpus are not published. The change is in the server's request conversion (`serve/frontend.py`) in the internal build named above.

## Notes / caveats
- Tools sent on a system message now render, but the output parser and `tool_choice` still use the request's top-level `tools`.
- `wo_eos` and `mask` are not passed through (the reference ignores `mask`).
- The `/v1/responses` path changes too (it shares the conversion); the comparison corpus does not cover it, the unit tests do.
- A live check on a running server (the engine's received ids against the expected ids, turn by turn) is designed, not run.

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output) or INFERRED (our own reading).
