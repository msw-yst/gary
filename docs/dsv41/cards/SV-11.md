# SV-11: Served benchmark on build 13s: one to eight users, prompt helper on and off, 4 and 8 slots
Status: finding · Date: 2026-11-13
Code: in the fork's release commit. Flags: build 13s's served environment (SV-10); arm B sets `DS4_PF_HELPER=0`; arm C sets 8 server slots (PAR 8).

## What and why
- The first end-to-end served measurement of the configuration being deployed, with a client like real use: sampled requests (temperature 0.6), synthetic 2K and 8K prompts, 512 new tokens (256 at 8K), and a 32K cold prompt with a passphrase to find.
- Arms: **A** prompt helper on, 4 slots (the served config); **B** helper off, 4 slots; **C** helper on, 8 slots (the engine's largest batch window; about 120 MB a card a slot).

## Prediction
- None for the matrix (a measurement). Pre-registered: no.

## Correctness
- Not an identity run. The 32K passphrase was found in both runs that reached it. Batched-vs-solo exactness is in SV-10.

## Timing
- Run 1, 13 Nov 01:12: pre-incident hardware (4 × RX 7900 XTX: XTX #1–3 Gen4 x16, XTX #4 Gen4 x8; power caps 294 / 272 / 272 / 261 W, −50 mV; 4 × MI50 at 135 W, Gen4 x4; MI50 DPM `high`). Arms A, B, C.
- Run 2 (arm B repeated), 13 Nov 19:43: after the hardware change (HW-09).
- "Total" = decode tok/s summed over users while all are active; "with prefill" = all tokens over the whole wall time. Time to first token (TTFT) per request.

## Verdict
- **One user: about 124 tok/s at a 2K context (8.05 ms a token) and 115 tok/s at 8K, drafter on.** Several users, 4 slots: 146–153 tok/s in total at 2–4 users. **8 slots: 186 tok/s in total at 8 users**, about +25 % over the 4-slot plateau, for about 4 % on a single user (118.6 against 124.3 tok/s).
- **Prompts are read one at a time.** TTFT steps by about 2.9 s per 2K prompt and about 7.5 s per 8K prompt in the queue, so at 8 users the last user waits 25 s (2K) or 61 s (8K). That, not decode, is the multi-user limit now [I].
- **The prompt helper:** in the same run it cut 2K TTFT from 4.3–4.4 s to 2.5–3.0 s (about −40 %). In run 2 (helper off, later, on the changed XTX set) 8K TTFT was 5.9 s and 32K 18.9 s, against 6.9 s and 25.9 s with the helper on in run 1. Across those two sessions the helper looks slower from 8K up [I]; the like-for-like answer is the final benchmark on build 15 (SV-14), which runs helper on in the same harness. *Update, 13 Nov:* build 15's served 32K TTFT with the helper on was 23.1 s (SV-14), and a same-session served A/B then showed the helper slower than no helper from 16K up, faster at 2K (PF-13).
- Arm B's first run hung in a prompt read after six requests; its second run completed (SV-12).

## Notes / caveats
- Synthetic prompts, one session per arm, 2–3 reps; the 2-user A reps include one slow rep (128.7).
- In each phase the lines of the extract run in matrix order: 1 user at 2K (3 reps), 1 user at 8K (2 reps), then 2, 3, 4, 6, 8 users at 2K and the 32K row; arm C: 1, 4, 6, 8 users at 2K, then 8 users at 8K.
- These TTFTs are for cold prompts. A continued agent conversation reuses its earlier state and reads only the new tokens (SV-15).

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output) or INFERRED (our own reading).

Sources: `data/cards/SV-11/` (SHA256SUMS, served-matrix.txt); sanitised copies, checked by `SHA256SUMS`. Originals are held privately.
