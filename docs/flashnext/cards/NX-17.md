# NX-17: MTP on the shared pool at 2-8 users per worker, and the verify window
Status: finding (`STRATA_BATCH_MTP_ROWS`, `STRATA_BATCH_MTP_OFF_ABOVE` not kept) · Date: 2026-11-21 / 2026-11-22
Code: MTP in batch windows as NX-15. The two window switches are on the development branch, not yet in this tree ([Settings](../README.md#settings)). Flags: `STRATA_BATCH_MTP=1`; `STRATA_BATCH_MTP_ROWS=R` (verify window up to R rows, 2-16; default 8); `STRATA_BATCH_MTP_OFF_ABOVE=N` (no proposals in a window over more than N live slots; default off).

## What and why
- NX-15 measured MTP on the pool at one user per worker (1.11-1.17x the baseline). Agents come in groups; does MTP still pay at 2, 4 and 8 users per worker?
- Then: the MTP verify window holds 8 rows, so at 8 live slots (2 rows each) a step needs two windows. Does a 16-row window, or dropping proposals above 4 live slots, fix 8 users per worker?

## Prediction
- Pre-registered: yes. MTP on / off: 2+2 55-65 tok/s (1.35-1.6x), 4+4 35-45, 8+8 18-24 [ESTIMATE]. Bar: MTP worth enabling if on / off >= 1.10 at every level of 2 or more per worker.
- Window test: bar = the best MTP arm >= MTP off at 8+8, with no regression at 4+4 (>= 0.97x the 8-row window). 16-row window at 8+8 17-21 tok/s [ESTIMATE].

## Correctness
- Reference text on both workers in every configuration; batched == solo, loaded == alone, worker 1 == worker 2 8/8 (MEASURED).
- Every speed-prompt text is the same with MTP on and off, with 8 and 16-row windows, with no proposals, and across two hot-set sizes (MEASURED). These are the short-prompt checks; see the README's [exactness note](../README.md#how-to-read-the-numbers).

## Timing
- Hardware: 2 × RX 7900 XTX 24 GB (272 W cap), 4 × Instinct MI50 16 GB (135 W cap), EPYC 7642 (48 cores), 256 GB DDR4-2666.
- Software: Strata v0.2.9 plus this fork's changes; the pool on the ROCm 7.2.1 HSA runtime. Kernel version: not captured in the published extracts.
- Workload: 8 prompts × 384 tokens, temperature 0, users split evenly; arms alternated, 2 trials each. The window test ran after MI50 #3 was reseated (NX-18), with MTP off re-measured in the same run.

Dropping proposals still ran each drafter's catch-up, +5.7 ms a window over MTP off (MEASURED from engine lines; the reading INFERRED).

## Verdict
- MTP on the pool pays up to 4 users per worker (+28 % at 2, +6-7 % at 4) and loses at 8 (-13 %). With it, 4 agents get >= 40 tok/s on short prompts (slowest 45.8-47.8).
- Neither window switch reaches MTP off at 8+8; both stay opt-in and unused. [NX-20](NX-20.md) (adaptive MTP) replaces the interim rule "MTP off above 4 users per worker".
- All measured loaded levels came in below the predicted ranges.

## Reproduce
- "Layout 3" in [README.md](../README.md#launch) with `STRATA_BATCH_MTP=1` and the MTP cache sizes (4 slots: hot 4,300 / MI50 5,100; 8 slots: hot 3,150 / MI50 5,400).

## Notes / caveats
- The first table ran before the reseat, the second after it; their absolute numbers do not compare (NX-18).
- The first table's 8-slot MTP-off comparators come from an earlier build of the same code (at 4 slots the two builds agreed within 1.5 %).
- Absolute numbers come from a private prompt set (8 prompts, not published); ratios between arms of the same run are the comparable quantity.

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output), ESTIMATE (our arithmetic) or INFERRED (our own reading).
