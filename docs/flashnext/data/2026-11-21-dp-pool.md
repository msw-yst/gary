# Shared MI50 pool: run data (2026-11-21, data extract)

Sanitised extract of the run record behind [SHARED-POOL.md](../SHARED-POOL.md) and cards NX-14 to NX-16. Per-cell logs and
kernel logs are kept privately.

Labels: XTX A, XTX B (RX 7900 XTX 24 GB); MI50 #1-#4 (Instinct MI50 16 GB, 135 W cap; #3 is the slow-link card).
Standard environment on every server in this file: the tuned prompt-reading rows (the packaged default),
`STRATA_BATCH_SELF_COMMIT=1`, `STRATA_TSUM=1`, `STRATA_B6_MMVQ_ROWS=1`, `STRATA_POOL_WAIT=pred`, the fast helper transport
(`STRATA_HELPER_FAST=1 STRATA_HELPER_GRAPH=1 STRATA_HELPER_THREADS=1`, own `STRATA_HELPER_CPUS` per server). MTP off unless
stated. Client: the 8 standard prompts, 384 tokens, temperature 0, presence_penalty 0, users split evenly over the two servers.
Per agent = median over users of streamed chunks per second; agg = aggregate tok/s while all streams are active.

Arms: **baseline** = two one-card servers (XTX A + MI50 #1, #2; XTX B + MI50 #3, #4), automatic cache sizes;
**pool** = two workers in one pod, worker 1 (XTX A) fills and exports the four MI50 caches, worker 2 (XTX B) imports them.

**Runtime confound.** Every pool cell (sections 2-6) ran an engine build with the ROCm 7.2.1 HSA runtime swapped in (export
needs it); every baseline cell ran the build with its bundled runtime. The pool / baseline ratios below therefore include any
difference between the two runtimes and builds, not only the pool. A baseline on the same runtime is being measured; these
numbers will be updated when it is in.

## 0. XTX power cap A/B (two one-card servers, PARALLEL 4 each)

Both XTX caps set live between levels in the order 402, 303, 272, 402 W (272 W is the driver's floor, 303 W the default).

| Cap (both XTX) | 4 users: per agent / agg | 8 users: per agent / agg | XTX A / B mean W at 8 users (max) |
|---|---|---|---|
| 402 W, first | 36.18 / 154.5 | 24.42 / 205.0 | 267 / 265 (292 / 310) |
| 303 W | 36.73 / 153.5 | 24.51 / 204.2 | 273 / 273 (319 / 301) |

No measurable cost in decode: all rows agree within 0.3 % aggregate (the first 4-user per-agent value is the warm-up level).
Uncapped, each XTX draws ~15-20 W more on average. Prompt reading (compute-bound) was not tested. MI50s drew 43-58 W each.

## 1. HIP IPC smoke test (`pool_ipc_smoke`, gfx906)

A holder allocates 16 synthetic Q4_K/Q5_0 experts (2560 x 640, the Q4_K pack's types) on one MI50 and exports the allocation
(`hipIpcGetMemHandle`). Clients open it, run `native_expert_grouped` over 7 imported experts (one 4-user helper launch) and
bit-compare against the same blobs in a private allocation.

| Setup | Result |
|---|---|
| HSA runtime bundled with the engine build | export refused: `hsa_amd_ipc_memory_create` returns `HSA_STATUS_ERROR_INVALID_ARGUMENT` at every size (12 MB - 1.2 GB), also with `HSA_ENABLE_IPC_MODE_LEGACY=1`; on the XTX too |
| ROCm 7.2.1 HSA runtime, alone or under the engine's own `libamdhip64` | export works |
| Holder and clients in one container | import works; imported == private bytewise, stable after the concurrent phase |
| Separate containers, own network namespaces (with or without a shared PID namespace, extra capabilities or privileged) | import fails (`invalid device context`, or `invalid device pointer` after a 10.8 s timeout) |
| Separate containers sharing host network and PID namespaces, or one podman pod with `--share net,pid,ipc` | import works, bitwise equal |

Concurrency (one container, 7 experts, 1 token, back to back): one client 90.9 us p50 per launch + sync; two clients at once
153.8 us p50 each (p99 173 us): 1.18x the throughput of one client.

## 2. First pool trial and the stall

Pool: hot prefix 4,700 experts on each XTX, MI50 caches 5,000 slots each; both workers logged
`CUDA0 4700, pool 19876, CPU path 0 of 24576`. Each worker had its own private 68 GB pinned expert arena.

| Cell | Users | Per agent | Agg | vs baseline |
|---|---|---|---|---|
| baseline | 4 (2+2) | 36.60 | 153.4 | - |
| baseline | 8 (4+4) | 24.37 | 204.9 | - |
| pool, one trial | 4 (2+2) | 38.85 | 166.2 | +6.1 % / +8.3 % |
| pool, next cell | - | - | - | stalled (below) |

Exactness where measured: reference `a7ae6623797f17fe` on both pool workers and both baseline servers; pool worker 1 ==
worker 2. Baseline: batched == solo 4/4 and 8/8 on both servers, alone and loaded; loaded == alone 8/8; server 1 == server 2
2/8 (different placements).

The stall: the importing worker's first request made no progress for 60 s. The engine watchdog restarted it; the kernel
reported KFD queue eviction ("queue evicted") for its queues, and the restarted engine hung again at its first request. The
kernel then reported hung kernel workers blocked behind `svm_range_restore_work` /
`amdgpu_amdkfd_restore_userptr_worker` (6 reports, 122-245 s). The cell was stopped; the stop was clean, no reset, no
process left in D state. Host RAM in use: 190 GiB of 251 with two private arenas.

## 3. First retry, one shared expert arena (`--shared-expert-arena`)

Both workers loaded with CPU path 0; worker 2 logged "shared expert arena: already filled by another engine". Host RAM 124 GiB
(against 190). Reference hash on both workers. A kernel-log watch for queue eviction, hung tasks, resets and ring timeouts was
armed, plus a 30 s no-progress watch in the client.

The cell stopped at the client's 30 s watch. Cause: the thermal guard paused worker 2 for 32 s (XTX B memory at 94 C, the
guard's limit then). Worker 2's engine log shows normal batched windows up to the stop (383 windows, 3.99 rows, 29.1 ms per
window). The kernel log had no line from the watch list. Afterwards the thermal pause moved to 100 C junction / memory (warning
from 97 C, resume at 90 / 92 C after at least 30 s), and the client's watch stopped counting paused time.

## 5. One user per worker, MTP off

One user on worker 1 with worker 2 idle (3 prompts in turn), the same on worker 2, then one user on each at once. Pool: hot
4,700, MI50 caches 5,000 (4,969 used), CPU path 0. Baseline: automatic caches (XTX 5,301 / 4,839 + 2 x 5,586 MI50 each;
16,473 / 16,011 of 24,576 on GPUs). One trial each.

| 1 user | Pool tok/s | Baseline tok/s | Ratio |
|---|---|---|---|
| on worker 1 (XTX A), the other idle | 54.35 | 51.48 | 1.056 |
| on worker 2 (XTX B), the other idle | 53.59 | 50.31 | 1.065 |
| one on each, per user | 52.26 | 47.48 | 1.101 |
| one on each, aggregate | 104.5 | 95.0 | 1.100 |

Pool: reference hash on both workers; worker 1 == worker 2 3/3 on the speed prompts (baseline 1/3). A user beside the other
worker's user loses 3.6 % (pool) against 7.8 % (baseline, where the two servers' CPU paths share DRAM). About 6 busy cores
per active pool worker against about 15 per baseline server.

Before this, worker 1's routing was recorded on agent-turn-like traffic (48 coding-agent prompts over ~12k-character source
excerpts, 4 at once, 512 tokens; 21,376 generated tokens) and turned into a ranking with `tools/make_profile.py` (24,127
pairs ranked from the trace, 449 from the shipped profile). It is the input for placement-tuning step 2.

## 6. One user per worker with the MTP drafter

Same workload as section 5, `STRATA_BATCH_MTP=1` on every server. Pool: hot 4,300, MI50 caches 5,100 (the drafter costs
~443 XTX slots), CPU path 0. Baseline: MTP on, automatic caches. Alternating P B P B, two trials each.

| 1 user, MTP on | Pool tok/s (trials) | Baseline tok/s (trials) | Ratio |
|---|---|---|---|
| on worker 1 (XTX A), the other idle | 86.52 (86.25, 86.78) | 78.21 (78.06, 78.35) | **1.106** |
| on worker 2 (XTX B), the other idle | 86.95 (86.68, 87.22) | 74.42 (74.35, 74.48) | **1.168** |
| one on each, per user | 83.13 (82.96, 83.29) | 72.47 (72.40, 72.53) | **1.147** |
| one on each, aggregate | 166.3 | 145.0 | 1.147 |

MTP's own gain at 1 user on worker 1: pool 54.35 -> 86.5 (1.59x), baseline 51.48 -> 78.2 (1.52x). Drafts accepted ~90 % on
these prompts (engine log: 120 of 133, 184 of 193). Trial-to-trial spread at most 0.6 %.

Exactness:
- Pool, MTP on: reference `a7ae6623797f17fe` on both workers; batched == solo 4/4 and 8/8 on each worker, alone and loaded;
  loaded == alone 8/8 on both; worker 1 == worker 2 8/8. The solo texts and the speed prompts' texts equal the MTP-off pool's
  (for example `109d175331a43265`, `85757a610959e46b`): **in the pool, MTP changes no bit of the output.**
- Baseline, MTP on: reference `a7ae6623797f17fe` on both servers as well.
- Open: the earlier one-card MTP arm (decode A/B and pool-wait studies, older engine and environment) gave `da29bc7d5a0ba433`.
  With today's standard environment neither arm gives it. Not re-baselined.

Host RAM 126 GiB (pool) against 191. Kernel log clean. Thermal max: XTX A junction 86 / memory 84 C, XTX B junction 92 /
memory 94 C, no warning, no pause.
