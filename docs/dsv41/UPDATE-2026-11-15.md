## Build 17 against build 16

- 8 users: 180.3 → 202.8 tok/s (**+12.5 %**). 4 users: +5.3 %.
- One user: 8K first token −12.5 %, 2K first token −4.7 %, 8K decode −1.9 %, 2K decode +0.7 %.
- 32K cold first token: +3.0 %. Disk is ruled out (0 MB read, 0 major faults in both builds).
- Identical output; zero picks counted twice. Why build 16 was slower for one user, and how the fix keeps the speed and
  stays correct: [HX-29](cards/HX-29.md), [HX-30](cards/HX-30.md).

## Swap instead of evict (`DS4_ECSWAP=1`, build 18)

- When the cache moves an expert from an MI50 up to an XTX, the cold expert it pushes off goes into the freed MI50 slot
  instead of the host-RAM path.
- Correct under heavy churn: 1,592 handovers in a 200-prompt soak, 0 counted twice, 0 dropped, 0 mismatches. The
  host-RAM path stayed empty throughout.
- A server's 2K first token after 50 earlier prompts: 2.67 → 2.06 s (**−22.7 %**). Fresh-server cells unchanged.
- The one cell that looked slower (2K decode +1.3 %) is one request taking a different sampled token path; time per step
  is unchanged. [HX-32](cards/HX-32.md).

## Settle the cache after the first token (`DS4_SETTLE_AFTER`): parked

- It saves only 0.13 s of the 32K first token, not the 0.45 s we predicted.
- Its 8K decode "gain" (−5.8 %) is one request's token path, not a speed-up.
- After a short answer, a leftover settle can hold up the next request by up to about 1.6 s (ESTIMATE). Agent
  tool-call traffic looks like that, so it stays parked until that is fixed. [HX-31](cards/HX-31.md).
- The rest of the 32K gap (about 0.4 s against build 16) only appears after many earlier requests. Cause not shown.

## Where the MI50 helper's time goes when serving

- Served, one user, the lead XTX waits for the helpers 9–13 % of each decode step (1.46 of 16.6 ms with one token in
  the window, 3.44 of 25.7 ms with four). In one process it is only 0.50 of 12.6 ms.
- Graph replay on the XTXs saves 0.4–0.9 µs a kernel; the real gap between kernels stays about 2.9 µs. Not worth building.
- Next: a faster helper head (`DS4_HSTEP_HEAD`), not yet measured. [FG-18](cards/FG-18.md).

## Host memory and CPU

- The engine's 123 GB is the expert RAM store (copies of experts the GPUs hold, used for prompts over 8K tokens and the
  host-RAM fallback), not the Engram table.
- The 110.6 GB Engram table is read through the page cache (7.4 GB of it was resident). A trace build that gives
  identical output now measures its hot set under load. The SSD answers a 4 KiB random read in 59 µs at queue depth 1.
- Serving uses about 4–5 cores, with bursts of 14–16 while reading prompts. [HW-11](cards/HW-11.md), [ME-12](cards/ME-12.md).
