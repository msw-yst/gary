# NX-10: Tuned hipBLASLt rows for the experts' prompt GEMM (the new exactness reference)
Status: kept (default; re-baselined) · Date: 2026-11-21
Code: in the fork's `flashnext-amd` commits: the packaged table `tools/hip/gfx1100-hipblaslt-100200.txt`. Flags: none to use it; `STRATA_PF_GU_LEGACY=1` restores the old kernel and the old bits.

## What and why
- Reading a prompt, the experts' FP16 gate/up GEMM (N 1,280, K 2,560) took 40 % of a chunk: the packaged hipBLASLt table had no row for that shape, so every call fell back to rocBLAS's default FMA kernel at ~2.4x the cost per FLOP of the tuned down GEMM.
- hipBLASLt has 7 algorithms for f16-in / f32-out on gfx1100. A sweep picked the fastest per rows-per-expert M: 1145 (M <= 136), 1146 (137-200), 1147 (201+); plus 1145 for the down GEMM at M <= 32 (bit-identical to 1147 there).

## Prediction
- Cycle 1 measured one borrowed row (1147 everywhere): 22-24 % shorter TTFT, different bits.
- Pre-registered: the adoption depended on a maintainer decision to re-baseline exactness, taken before cycle 2.

## Correctness
- **Changes the bits** (matrix cores sum in another order; same precision class). GEMM max |difference| 8-9e-6 of the largest output; relative L2 against an FP64 product 7.9e-6 vs 9.0e-7 for the old kernel; decoded text first diverges at token 21 of 256, mean top-5 KL 3.0e-3 before it (MEASURED). New reference hashes in the data file.

## Timing
- Hardware: one RX 7900 XTX with two MI50 helper caches; EPYC 7642, 256 GB DDR4-2666.
- Software: Strata v0.2.9 plus this fork's changes on ROCm 7.2. Kernel version: not captured in the published extracts.
- Workload: cold prompts of 38-52k tokens (source code), temperature 0, 512 tokens out; one-card server with MTP, prompt cache, PARALLEL 4.
