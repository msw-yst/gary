# NX-14: Two XTX workers sharing one MI50 expert pool
Status: kept (opt-in) · Date: 2026-11-21
Code: in the fork's `flashnext-amd` commits. Flags: `STRATA_POOL_EXPORT=<manifest>` (worker 1), `STRATA_POOL_IMPORT=<manifest>` (worker 2), `--shared-expert-arena` (`STRATA_SET="shared-expert-arena=<file>"`), `STRATA_POOL_VERIFY`, `STRATA_POOL_WEIGHTS` (not used in these runs). Design: [SHARED-POOL.md](../SHARED-POOL.md).

## What and why
- Two one-card servers beat tp2 at 2-8 users but each runs about a third of the experts on the CPU (DRAM-bound, in series with the GPU). Tensor parallel puts every expert on a GPU but barely shortens the dense path. The pool keeps one-card engines and gives both all four MI50s: one engine fills the MI50 caches and exports them as HIP IPC handles, the other maps them and drives the cards with its own helper threads. Both cache the same hot prefix on their XTX; every other expert lives on exactly one MI50; nothing goes to the CPU.

## Prediction
- Bars, written before the runs: per agent >= 1.10x the baseline at 4 users and >= 1.20x at 8; 4 agents at >= 40 tok/s; above tp2 at 8 users. Abort: below 1.05x at 8 users after one tuning pass; the other worker's load costing more than 15 %; any exactness failure.
- Estimate: ~31 tok/s per agent at 4 users per worker, 43-45 at 2, ~21 at 8 (ESTIMATE).
- Pre-registered: yes.

## Correctness
- Reference `a7ae6623797f17fe` on both workers; batched == solo 4/4 and 8/8 on each worker, alone and loaded; loaded == alone 8/8 on both; worker 1 == worker 2 8/8 (two separate servers: 2/8). CPU path 0 of 24,576 in every pool cell (MEASURED).

## Timing
- Hardware: 2 × RX 7900 XTX 24 GB, 4 × Instinct MI50 16 GB (135 W cap), EPYC 7642 (48 cores), 256 GB DDR4-2666.
- Software: Strata v0.2.9 plus this fork's changes on ROCm 7.2 (the runtime in Strata's ROCm image). Kernel version: not captured in the published extracts.
- Runtime: the ROCm 7.2.1 HSA runtime under the engine (the bundled one refuses IPC export); both workers in one podman pod with `--share net,pid,ipc`.
- Workload: 8 prompts × 384 tokens, temperature 0, presence 0, users split evenly; pool and baseline alternated, 3 + 3 trials at 4 slots per worker, 2 + 2 at 8.
- Baseline: two one-card servers (XTX A + MI50 #1, #2; XTX B + MI50 #3, #4), same engine settings, MTP off, but on the engine's bundled HSA runtime (see the caveat below).

## Verdict
- Kept as an opt-in layout: exact on every check and faster per agent at every load measured. The 8-user bar (1.20x) was missed; 4 agents reached 39.82 tok/s on average, a hair under the 40 bar; at 8 users it is well above tp2 (28.2 vs 21.2, tp2's aggregate / 8 = 169.4 / 8 as pre-registered; ~19.4 per agent). It came in 10-20 % under the estimate at every level. Placement tuning is next.

## Notes / caveats
- **Runtime confound:** every pool cell ran an engine build with the ROCm 7.2.1 HSA runtime swapped in; every baseline cell ran the build with its bundled runtime. The ratios include any runtime / build difference, not only the pool. A same-runtime baseline is being measured; these numbers will be updated when it is in.
- The first trial, with two private 68 GB pinned host arenas, stalled in the kernel driver (KFD queue eviction whose restore never completed). With one shared arena it did not recur over 10 cells (5 pool cells, about 58 min of pool cells). Memory-pressure eviction is the likely cause (INFERRED), not proven.
- A thermal guard set at 94 C memory stopped one retry; XTX B's memory reached 94 C in one cell. The guard limit was raised to 100 C.
- Measured runs used the plain round-robin stripe over the MI50s; the slower-link weight (`STRATA_POOL_WEIGHTS`) is the first tuning step, not in these results.
- Absolute numbers come from a private prompt set (8 prompts, not published); ratios between arms of the same run are the comparable quantity.

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output), ESTIMATE (our arithmetic) or INFERRED (our own reading).
