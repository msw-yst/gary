# NX-16: XTX power cap costs nothing in decode
Status: finding · Date: 2026-11-21
Code: no engine change. Flags: the XTX `power1_cap` (sysfs), set live between levels.

## What and why
- Whether the XTX cards can run at their lowest power cap (272 W; default 303 W, maximum 402 W) without losing decode speed.

## Prediction
- No numeric prediction was recorded before the run.
- Pre-registered: no.

## Correctness
- Not applicable (no engine change).

## Timing
- Hardware: 2 × RX 7900 XTX 24 GB, 4 × Instinct MI50 16 GB (135 W cap), EPYC 7642 (48 cores), 256 GB DDR4-2666.
- Software: Strata v0.2.9 plus this fork's changes on ROCm 7.2 (the runtime in Strata's ROCm image). Kernel version: not captured in the published extracts.
- Workload: two one-card servers, PARALLEL 4 each, 4 and 8 users, 384 tokens, temperature 0; caps in the order 402, 303, 272, 402 W.

## Verdict
- No measurable cost in decode (within 0.3 % aggregate). Uncapped, each XTX draws ~15-20 W more for the same speed. We run at 272 W.

## Reproduce
- Set `power1_cap` on each XTX between runs of any layout.

## Notes / caveats
- Prompt reading is compute-bound (~265 W at a 272 W cap) and was not tested; a cap can bind there.
- Absolute numbers come from a private prompt set (8 prompts, not published); ratios between arms of the same run are the comparable quantity.

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output), ESTIMATE (our arithmetic) or INFERRED (our own reading).
