# ME-12: An Engram access-trace build that changes nothing, and the SSD's random-read latency
Status: method (trace build not in the published release) · Date: 2026-11-15
Code: not in the published release; the code is not in the public commit. Build 17 plus `DS4_ENGRAM_TRACE=1` (default off; about 120 lines of counters): per 4 KiB page of the Engram table, a read count and the last-read time, a reuse-gap histogram, a 10 s line and a page dump every 300 s.

## What and why
- The Engram table is 110.6 GB on SSD and is read through the page cache (HW-11). How much of it must stay in RAM depends on the hot set, which only a trace under real load shows.
- Before the trace build serves real traffic, it must give build 17's tokens. The SSD's latency is measured alongside, to turn page misses into milliseconds.

## Prediction
- Identity: trace on and off both identical to build 17. Not timed.

## Correctness
- **PASS:** build 17, trace off and trace on: same tokens, same placement, 0 experts on the host-RAM path (MEASURED). Decode 75.77 / 75.69 / 75.47 tok/s (one run each; not a timing design).
- The trace saw, in 814 tokens: 39,048 lookups, 27,048 row-cache hits, 12,000 reads touching 12,376 pages (379 straddling a page) (MEASURED).

## Timing
- 15 Nov, 4 × RX 7900 XTX + 4 × MI50. SSD: the pack's NVMe drive, 4 KiB random reads with O_DIRECT, 4 s at each queue depth.

## Results
| queue depth | IOPS | latency p50 / p99 / p99.9 | label |
|---|---|---|---|
| 1 | 16,425 | 59 / 69 / 74 µs | MEASURED |
| 8 | 106,789 | 70 / 111 / 137 µs | MEASURED |
| 32 | 84,633 | 359 / 1,662 / 2,517 µs | MEASURED |

## Verdict
- **The trace build is safe to serve with.** It goes into the load run.
- Back of the envelope: Engram needs 48 row reads a token. If all of them missed RAM, decode would pay about 48 reads at queue depth 8, about 0.5 ms a token, and a 32K prompt about 1.5 million reads, about 14 s [I]. So the hot-set size decides whether RAM can be cut, and that is what the trace measures.

## Reproduce
- Not reproducible from the published code: the trace switch is not in the public commit. The SSD figures are a plain 4 KiB O_DIRECT random-read test.
