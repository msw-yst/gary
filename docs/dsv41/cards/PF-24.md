# PF-24: Prompt reuse already works; agent turns pay a fixed ~2.15 s a read; a settle hold (`DS4_CACHE_PF_HOLD`) staged

Code: none for the study (desk study of release candidate r2a, `stack-r2a-rc1` 8c7aa75e). The staged A/B uses internal build `pfag1-r1` 8339170a (r2a + `pfhold-r2` 73d3a2c6, host code only). Flags: `DS4_SETTLE_MS` (existing), `DS4_CACHE_PF_HOLD=1` (new, default off).

## What and why
- After PF-20 a cold 32K prompt still takes ~26 s. The question: what do agent loops actually pay, does prefix reuse work, and what is left to cut?

## Prediction
- None (desk study). Its ranked savings below are estimates.

## Correctness
- Not applicable. Prefix reuse is exact: reused and re-read prompts give identical outputs under identical placement (MEASURED earlier).

## Timing

## Results
| item | result | label |
|---|---|---|
| prefix reuse | exists and serves: continuation in place, 4 checkpoints, 4 RAM slots + 16 GB disk spill, pinned system prompt; e.g. "1,659 tokens = 1,658 reused + 1 read in 37 ms" | MEASURED (logs) + code |
| reuse on agent traffic | 92–97 % of prompt tokens | MEASURED |
| fixed floor per read of ≥ 512 new tokens | ~2.15 s: each read DMAs the ~4,245 experts not held by the MI50s, 19.9 GB a card (~80 GB a read), at 9.2 GB/s a card | MEASURED / INFERRED |
| reads under 512 new tokens | window path, ~8.3 ms a token (384 tokens: 3.3 s) | MEASURED |
| cold 2K–14K | XTX wait ~40 % of the read on the MI50 helpers; the MI50 prompt-tile kernel (PF-12) never engages on MXFP4 | MEASURED + code |
| 32K | linear in layer-rows (13.9 ms a layer-chunk + 35.4 µs a row-layer; predicts 32K 25.84 vs 25.8 s) | INFERRED from MEASURED points |
| warm 2K first token | 3.2–3.3 s (the published 3.6 s was a mean over a cold warm-up curve) | MEASURED |

Ranked levers (served, one user, warm; ESTIMATES): (1) compute unheld experts on the CPU for small reads, or a faster stream: agent turn −0.65 to −1.0 s; (2) an MXFP4 one-pass helper kernel: 32K −2 to −2.7 s; (3) prompt-skip level 2: 8K −1.8 s (needs a quality gate; see PF-23 for a related mode that failed); (4) the end-of-read settle (`DS4_SETTLE_MS=0` or `DS4_CACHE_PF_HOLD=1`): −0.2 to −0.35 s a read.

## Verdict
- **Reuse is not the lever; the per-read expert stream is.** More reuse is worth ~1 % of agent wall time (INFERRED). Agent loops pay ~2.15 s on every read of 512 or more new tokens.
- The cheapest item, the end-of-read settle, was staged as a live A/B: arms flag off / `DS4_SETTLE_MS=0` / `DS4_CACHE_PF_HOLD=1`, order L0 LS LH LH LS L0, exactness first, ~2 box-hours. It replaces an earlier hold package whose bar (−10 % at 2K) would have failed even if the hold worked perfectly.
