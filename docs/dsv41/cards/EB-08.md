# EB-08: Expert files memory-mapped instead of an 83 GB pinned copy (`--mmap-experts on`)
Status: kept (served from build 13s) · Date: 2026-11-12
Code: in Gary's release commit. Flags: `--mmap-experts on` (default off).

## What and why
- At load the engine copies the experts that could run on the CPU lane into 83 GB of pinned host memory. Since every expert now lives on a GPU (TP-04 onwards; the CPU lane holds none), that copy is only a fallback for prompt chunks. Memory-mapping the files instead saves the pinned RAM, which matters for anything else that needs host memory (EB-05, QA-04).

## Prediction
- Prompt time within ±3 %; load 37 s shorter (the pin step); 83 GB less pinned memory. Pre-registered: yes, in the run's prereg.

## Correctness
- Identity IDENTICAL at short context and at 32K, with equal placement (MEASURED).
