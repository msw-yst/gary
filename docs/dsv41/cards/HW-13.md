# HW-13: Host RAM at 2933 MT/s instead of 2666: +14–16 % memory bandwidth, no first-token change while the prompt path was disk-bound
Status: kept (hardware setting; watch for memory errors) · Date: 2026-11-19
Code: no engine change. Host firmware setting only.

## What and why
- The host's 16 DIMMs ran at 2666 MT/s because four of them are rated 2666; the board allows 2933 with two DIMMs a channel (REPORTED, from the 18 Nov platform check). The CPU lane's expert kernel already ran at 85–90 % of the measured memory ceiling (FG-23), and native prompt reads spend most of their time in host copies (PF-15), so more bandwidth could help both.
- On 19 Nov the memory clock was set to 2933 in the firmware at the console, with the overclock option enabled.

## Prediction
- Desk estimate before the change: worth about 5–10 % of the prompt read while the host copies remain (INFERRED, PF-15's desk study).

## Correctness
- All 16 DIMMs trained at 2933 MT/s, 251 GB visible, no memory-error (EDAC / machine-check) reports at boot (MEASURED). Four DIMMs run above their rating; memory-error counts are being watched.

## Timing
- Bandwidth: the same CPU-only memory benchmark on 18 Nov (2666) and 19 Nov (2933), no GPU work, 8 GiB buffers, best of 5.
- First token: the native prompt staging profile (PF-15) run at 2666 at 12:13 and again as the first engine run after the reboot. Native MXFP4 pack, internal native build, the test machine's 4 XTX + 4 MI50.

## Verdict
- **Kept.** Bandwidth rose 14–16 %, more than the 10 % clock ratio (INFERRED: the fabric clock followed the memory clock).
- **No first-token gain while the prompt path read from disk:** the RAM copies got 12 % faster, but the file reads grew on a cold page cache and the total moved by 2–3 %, within what a cold start explains. The disk was hiding the RAM speed.
- Since then the disk has left the prompt path (PF-19: 0 GB a read), and with direct DMA the host copies too (PF-20); every PF-18 to PF-20 number was measured at 2933. A clean 2666 / 2933 A/B on the new prompt path, and on CPU-lane decode, has not been run.

## Reproduce
- Any read-bandwidth benchmark pinned to the host's cores, before and after the firmware change.

## Notes / caveats
- The first-token pair is not a clean A/B: one run before the reboot, one right after it, with a cold page cache.
- Four DIMMs above their rated speed: a long-run error check is the open item.

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output) or INFERRED (our own reading).
