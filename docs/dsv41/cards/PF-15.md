# PF-15: Where a native prompt read's time goes: the host copies the experts the XTXs do not hold, about 337 GB a 2K prompt
Status: finding (the fixes are PF-17 to PF-20) · Date: 2026-11-18 (profile and desk study 2026-11-19)
Code: not in the release commit of Gary, our fork of Strata (internal branch only: per-call-site read counters and a staging profile on the native build). Flags: measurement only.

## What and why
- On the native MXFP4 pack a 2K-token prompt took 15–20 s to its first token, against about 2.2 s on the 2.25-bit pack (QA-12). Agent turns pay that on every read of 512 new tokens or more. This card collects the four measurements that found where the time goes.
- Background: on native the XTXs hold 3,056 experts each in VRAM, the four MI50s 1,784 each, and the CPU lane 12,688 (238.9 GB), served from a host RAM store or the model files (MEASURED, placement lines). A chunked prompt pass sends every expert an XTX does not hold to that XTX, once per chunk.

## Prediction
- Each step had its own written prediction. The first one (that the disk reads came from Engram rows) was wrong; see the correction below.

## Correctness
- Counters and profiles only; no output-changing switch. A read-once switch built along the way was bit-identical (PF-16).

## Timing
- 18–19 Nov, the test machine: 4 × RX 7900 XTX (tensor-parallel 4) and 4 × MI50 32 GB helpers at 135 W; one EPYC Zen 2 16-core host, DDR4-2666. Native MXFP4 pack, internal native build. 2K and 8K prompts, one user, page cache dropped and the same warm-up before each arm.

## Results
| step | what it showed | label |
|---|---|---|
| 1. engine read counters (18 Nov) | first reading: the disk reads are Engram rows. **Wrong**: that check was a lower bound any reader passes. The Engram reader reads about 1.7 KB a prompt token, under 2.5 % of the disk reads | MEASURED (the correction from code and counters) |
| 1, corrected | a prompt pass reads about 170–190 GB through `read()` whatever the prompt length, and about 58 GB of it comes from the disk for a 2K prompt; first token 17.6–18.8 s for ~1.7K-token prompts | MEASURED |
| 2. per-call-site counters (18 Nov) | 99.5 % of the pass's `read()` is each tensor-parallel member reading a whole expert and keeping its quarter: 162 GB a 2K prompt | MEASURED |
| 2, same run | the stream's read-ahead asks the kernel for 198.5 GB a prompt of file pages for experts **already in the RAM store**, plus 40.4 GB for the others | MEASURED |
| 3. staging profile (19 Nov) | 2K first token 16.2–16.3 s; per prompt the 32 reader threads move 131 GB by file read (211 s of thread time) and 206 GB by RAM copy (188 s), plus 10.6 s of conversion: about 337 GB, about 21 GB/s | MEASURED |
| 3, same run | readers on CPU for 0.623 of their in-call time; run queue 0.055; block I/O 1.2 % of samples, page-cache churn 6 %, page faults 0; 8K prompt 17.7 s, same volume | MEASURED |
| 4. desk study (19 Nov) | a 2K prompt sends 12,688 experts × 4.70 MB (a member's quarter, already 4-bit) × 4 XTX = 238.6 GB; 14.75 of 16.2 s is waiting on host staging; PCIe about 3.7 GB/s a card | INFERRED (from step 3, the served logs and the source) |
| 4, same | the MI50 prompt helper was **off** on native (the MI50s were full), so the 7,136 experts the MI50s hold (56 % of the 12,688) were re-sent to the XTXs on every prompt | MEASURED (the engine's start-up line) |
| 4, same | agent turns of 300–511 new tokens took about 3 s; 512 and more about 24 s (263 of 307 turns on the slow side) | MEASURED (served logs) |

## Verdict
- **Native prompt reads are bound by the host copying experts to the XTXs, not by the GPUs, and not by the disk alone.** About 337 GB moves through host memory and the page cache for a 2K prompt. The disk adds to it because read-ahead pulls file pages for experts that are already in RAM.
- The ranked fixes from the desk study (ESTIMATES at the time): (1) raise the short-prompt cutoff (24 s agent turns → ~4–14 s; PF-17); (2) turn the MI50 prompt helper on (2K ~7–9 s; PF-18, PF-19); (3) DMA straight from the RAM store with (2) (2K ~2.5–4 s; PF-20). Measured a day later: 2K 15.2 → 3.33 s with all of them except (1) (PF-20).
- Faster RAM was estimated at 5–10 % while the copies remain; measured: no change while the disk was in the path (HW-13).

## Reproduce
- No published run: the native build and its counters are not in a release.

## Notes / caveats
- The staging profile's own pre-registered verdict is NO DATA: 48–49 % of the user-side samples could not be resolved to a symbol (bar 25 %). The run itself was clean (profiler overhead × 0.996–1.000), so the volumes and the on-CPU share above stand; only the split inside user space is missing.
- The desk study's estimates are labelled as such; PF-17 to PF-20 measured them.
- Bigger chunks are not a way out: 16K-row prompt chunks cost each XTX 397 expert slots (3,056 → 2,659), with decode × 1.215 (REPORTED, 18 Nov).

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output) or INFERRED (our own reading).
