# QA-19: Ranking experts for requantisation by weight-space error: no per-expert or per-layer signal; the sweep was stopped
Status: finding (hypothesis refuted; the sweep stopped) · Date: 2026-11-16
Code: none (desk study: offline requantisation of expert weights on a CPU). Flags: none.

## What and why
- The mixed-precision plan (QA-12) needs to know which experts lose the most when quantised lower. The first idea: requantise every expert to each level of the ladder and rank experts by their relative weight error, then spend native bytes where the error is largest.
- Stage A: layers 0 and 8, all 384 experts × 3 matrices, the full ladder (IQ1_M, IQ2_XXS, IQ2_S, IQ3_S). Stage B (all layers) was to follow.

## Prediction
- Weight-space relative error ranks experts for requantisation. Pre-registered: no.

## Correctness
- n/a (no engine run).

## Timing
- 16 Nov, CPU only on a second machine. Not a timing run.

- At each level the error is the same across experts, matrices and both layers: coefficient of variation 0.1–0.2 % (MEASURED).

## Verdict
- **No signal: weight error cannot rank experts.** The source experts are native MXFP4 (FP4 values with a scale per 32-value block). Relative error is scale-invariant and, with uniform importance, depends only on the value distribution, which is the same FP4 grid everywhere (INFERRED). So the damage an expert does reduces to how often it is picked × a per-level constant: a picks-only allocation.
- Stage B was cancelled and the CPU time returned. A per-expert signal has to come from real inputs: an importance matrix and output error on captured activations, and a per-layer noise sensitivity test. The per-level constants above stay as the price of bytes against error in the allocation.
- QA-12's later finding ("the share of native experts matters, not which ones") is consistent with this.

## Reproduce
- Requantise a few layers' MXFP4 experts to each level of the ladder and compare relative Frobenius error per expert; expect a flat line.

## Notes / caveats
- Two layers only; the cause (one shared FP4 grid) makes it very likely the other layers are the same (INFERRED).
- Uniform importance (no importance matrix) was used, which is what makes the error scale-invariant. With an importance matrix from real inputs the result can differ; that was not run in this stage.
