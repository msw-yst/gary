# HW-11: Host memory and CPU while serving: the 123 GB is the expert RAM store; Engram lives in the page cache
Status: finding · Date: 2026-11-15
Code: no new code; read from build 17's source and a served build 17 engine.

## What and why
- Planning other work on the same host needs to know what the engine's memory and cores are actually for. The engine's resident memory looked like it might be the Engram table. It is not.

## Prediction
- None written. A reading, not an experiment.

## Correctness
- n/a.

## Timing
- 15 Nov, served build 17, 4 slots, one-user and prompt traffic. Memory from the engine's memory accounting and its load log; CPU from per-thread samples.

## Results
| measure | value | label |
|---|---|---|
| engine anonymous memory | 123 GB; file-mapped 0.3 GB | REPORTED |
| what the 123 GB is | the expert RAM store: preloaded 119.8 GB, about 82 GB of copies of MI50-held experts plus about 38 GB of experts the XTXs also hold ("spare"). Auto size = free RAM − 12 GB, up to 149 GB here | REPORTED (engine load log) |
| what the RAM store is used for | prompts over 8K tokens (which read without the MI50 prompt helper and stream every expert not in XTX memory) and the host-RAM fallback; decode does not read it | INFERRED from the code |
| Engram table | 110.6 GB on SSD, one tensor (IQ4_NL, 144 B a row); 7.4 GB of it resident in the page cache at the time; **not** in the engine's memory | MEASURED (page-cache residency) |
| how Engram is read | 48 row reads a token, hash-scattered: 24 rows per Engram layer and token, 2 Engram layers (lookup code, `ds4_model.cu` about 9514–9634; header `ds4_model.cu` 527–547) | INFERRED from the code |
| who reads it | host threads with buffered `pread`, so through the page cache (`ds4_engram_io.hpp` 256–292), after a 256 MB in-RAM row cache; rows are then copied to the GPU. The unbuffered option is Windows-only (`ds4_model.cu` 4686–4708) | INFERRED from the code |
| page cache in use | about 100 GB (counted as "available") | REPORTED |
| CPU while serving | about 4–5 cores busy (one thread 89 %, four at about 69 %, one at 39 %, the main thread 27 %); load average about 2.3 | REPORTED (thread samples) |
| CPU during prompt reads | bursts of 14–16 cores for about 20 s | REPORTED (thread samples) |

## Verdict
- **The engine's 123 GB is the expert RAM store, not Engram.** Its size can be set (`DS4_STORE_GB` and related switches); how much smaller it can go is a long-prompt speed question.
- **Engram needs no engine change to cap its RAM**: it is page cache, so its cost is the hot set. The trace build (ME-12) measures that under load.
- Serving needs about 4–5 cores, with prompt bursts of 14–16.

## Reproduce
- Read the cited source lines in the release commit's `src/dsv41`. The RAM-store switches are in the release; the memory and CPU figures are from our machine.

## Notes / caveats
- Source line numbers are approximate and refer to build 17's tree; build 16's differ slightly.
- One sampling session, not a timed design; the core counts depend on the traffic.

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output) or INFERRED (our own reading).
