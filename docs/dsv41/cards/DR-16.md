# DR-16: Verify cost and DSpark acceptance by position, measured: an extra checked token costs 2.7–2.9 ms; positions 1–3 keep 71 / 67 / 69 %
Status: finding · Date: 2026-11-14
Code: in the release commit of Gary, our fork of Strata (build 16); no new code. Flags: the engine's forced-row batch test (`--batch-test --batch-rows`) and greedy drafter evaluation (`--spec-eval`), with `--dspark-block` / `--dspark-conf` per arm and `--no-expert-cache`.

## What and why
- The DSpine value model (DR-15) needed two numbers we did not have on a current build:
  - what one more verified row costs, at window sizes 1–16;
  - how often DSpark's draft at each position is kept.
- Earlier figures were a fitted 3.11 ms a row (build 11) and 2.66–2.70 ms (builds 12–13, DR-06 addendum). The desk model had used 3.7 ms as a pessimistic bound.

## Prediction
- No numeric prediction was written down. Pre-registered: no.

## Correctness
- Forced rows: every row's top token equals the reference row's in every cell (576 of 576 short, 288 of 288 long) (MEASURED).
- Two acceptance counts were compared: the engine's own per-position line and our round log. They differ by 1–2 rounds a position, because the two use different prompt paths (report only) (MEASURED).

## Timing
- 14 Nov, the 4 XTX + 4 MI50 test machine, build 16, the 2.25-bit pack, one process, expert cache off.
- Verify curve: forced windows of T = 1–16 rows for one sequence, eight short prompts (~0.7K tokens, 2 reps) and one 9K prompt (1 rep). Rows spread over 2 and 8 sequences were also timed.
- Acceptance: greedy, 7 agent-like prompts, three drafter settings.
- A first attempt the same afternoon stopped at its pre-check before any GPU work. The package expected an engine print that build 16 does not have; we fixed the check and queued it again.

## Verdict
- **An extra checked token costs about 2.7–2.9 ms on build 16, not 3.7.** It hardly depends on context, and rows from different users cost the same as rows of one user.
- **DSpark keeps about 70 % of the drafts it reaches at each of positions 1–3.** The confidence cut matters: without it, drafting is 20–26 % slower (13.17 ms a token, against 10.94 at block 5 and 10.47 at block 3 with the cut).
- **DSpine would pay only if it kept ~80–85 % at every position.** In long reasoning on another model it kept 57 % at 3 ahead (DR-15), the same as DSpark here, so the large case is not shown. A modest DSpine is worth about 1 % today.
- **Cheaper verify rows multiply any drafter's gain**, so the row cost is the lever to work on first (followed up in DR-12 to DR-17).

## Reproduce
- Build 16 with the drafter loaded: the forced-row batch test at T = 1–16 for the curve; greedy drafter evaluation at block 3 / conf 0.3, block 5 / conf 0.3 and block 5 / conf 0 for acceptance.

## Notes / caveats
- Greedy acceptance on 7 agent-like prompts. Served sampled acceptance on build 11 was 72.7 / 64.6 / 60.1 % (DR-06), close to this.
- The 14.15 ms one-row step is the fit's intercept from forced rows, not a drafter-off decode run.
- The 2.25-bit pack and build 16 only. Later builds and the native pack price rows differently: 4.69 ms on the native build (DR-13) and about 3.2 ms on release candidate r2a (DR-17).

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output) or INFERRED (our own reading).
