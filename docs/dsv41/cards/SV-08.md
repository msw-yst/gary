# SV-08: Build 11 under real agent traffic: serving profile from the server's own counters
Status: finding · Date: 2026-11-10
Code: in Gary's release commit (build 11 as deployed). Flags: build 11's (SV-06), drafter on (confidence 0.3, block 3), one request at a time, 131,072-token context.

## What and why
- Every timing card so far uses short synthetic prompts. This card records what the server did under a real workload: an agent task suite (multi-turn tool use) run one request at a time against the deployed server for about 30 minutes.
- The counters come from the server's own metrics endpoint, sampled every 2 s. They are cumulative from server start to the end of the run, which was stopped early (see Notes).
- The point is to see which slices matter under real use (long contexts, cache reuse, drafter acceptance on agent text) before choosing the next optimisation.

## Prediction
- None pre-registered. This is an observation of a workload, not a test of a change.

## Correctness

## Verdict
- **Contexts are long and mostly cached.** The mean request carried ~55,000 tokens of context, and ~95 % of it was reused from the previous turn. One conversation reached ~115,000 tokens, close to the 131,072 limit. So the context limit matters for agent use, and a larger one is being tested.
- **The drafter is worth ~+34 % on this traffic.** It was measured at 11.47 ms a generated token against 65 tok/s (15.4 ms) single-stream with the drafter off in SV-06, at 59 % acceptance [I: the two measurements differ in context length and prompt mix].
- **Prompt reading is a quarter of the wall time even at a 95 % cache hit rate.** It is a target alongside decode. Prefill on long prompts has its own card set (PF-*).
- **Decode at long context hasn't been broken down.** The decode profiles (HX-20) are at short context, and attention cost grows with context, so a context sweep comes next.

## Reproduce
- No published run. The task suite and its prompts are private. The counters shown can be read from any Strata server's metrics endpoint.

## Notes / caveats
- The run was stopped by choice partway through the suite, so that the server could be restarted at a larger context. These counters cover the requests up to that point.
- The decode figure includes drafting and verification. It isn't comparable to the drafter-off single-stream figures except as an end-to-end rate.
- "Prompt tokens actually computed" assumes every non-hit prompt token was computed in that request [I].

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output) or INFERRED (our own reading).
