# SV-14: Build 15 and the final served benchmark
Status: kept (build 15; identity PASS; served benchmark done; the release build is now build 16, SV-16) · Date: 2026-11-13
Code: in the fork's release commit. Build 15 = build 14 (`DS4_XK_QO`, FG-08) + `DS4_PF_TILE` (PF-12) + `DS4_TOPK_MB_BATCH` (FG-11). Flags on top of build 13s's served environment: `DS4_XK_QO=1 DS4_PF_TILE=1 DS4_TOPK_MB_BATCH=1`.

## What and why
- Build 15 merges the three changes that passed on 12–13 Nov into the build being deployed, and the final served benchmark measures it with SV-11's client and matrix (prompt helper on, 4 and 8 slots), so the two can be compared directly.
- A correctness phase was added first: build 14 against build 15 with the new flags unset (decode, drafter decode, batch test), build 15 as deployed (including 32K and 110K, where the prompt tiles must engage), and one served user.

## Prediction
- One user, decode: within ±2 % of build 13s. Time to first token: −15 % (−8 to −22 %) at 2K, 8K and 32K (PF-12). Several users: within ±2 %, because the batched top-k engages only from about 32K of context, beyond this matrix's multi-user prompts. Pre-registered: yes, in the build-15 proposal and its addendum, before the run.
- Identity: every comparison IDENTICAL.

## Correctness
- The merge touched one source file, with two additive conflicts, both kept; build 15 minus build 14 is exactly the batched top-k change plus the prompt-tile files. The machine code of 1,255 XTX and 1,335 MI50 kernels is identical to build 14, and the 17 prompt-tile kernels are identical to the tested port; the code-object size check passed (REPORTED from the build notes).
- The build itself rebuilds from its git tag (ME-10).
- **Identity: PASS.** Nine distinct single-process comparisons, all stdout IDENTICAL with the same expert placement and every load and engagement line present: flags unset (decode, drafter decode, batch test) and as deployed (the same three plus a 32K and a 110K prompt); one served user, greedy, 1,025 token lines: IDENTICAL (MEASURED, identity.txt). The prompt tiles engaged in every as-deployed arm; the batched top-k did not engage in these single-sequence arms, as expected (its own identity evidence is FG-11).
- The first pass stopped on a check-design error, not a difference: the batch-test comparison with the flags unset ran a check that counted a line both builds print. Its three comparisons were already IDENTICAL; the fixed phase re-ran them.

## Verdict
- **Build 15 passed its identity phase.** It gives exactly build 14's tokens with its new flags unset and as deployed. This release ships build 16 (SV-16), which gives build 15's tokens; served, build 15 had the double count of HX-28, which build 16 fixes.
- **Served, prompts got faster and decode stayed put:** TTFT 2.6 → 2.2–2.5 s at 2K (−4 to −15 %), 6.9 → 5.9 s at 8K (−14 %), 25.9 → 23.1 s at 32K (−11 %), and the last of eight 8K users waits 52 s instead of 61. One-user decode +0.2 %, eight users −0.3 %. All three predictions held.
- This is build 15 on today's hardware, not a clean A/B: the XTX set changed between SV-11's run and this one (HW-09).
- **Open:** helper on, the 32K TTFT (23.1 s) is still slower than SV-11's helper-off run on the same cards (18.9 s). PF-13 measured it: served, the MI50 prompt helper is slower than no helper from 16K up. A fix that switches the helper off above a prompt length was built afterwards; it is in build 16 (PF-13, SV-16).

## Reproduce
- No published run: the code is in the release commit; a scripted public re-run has not been prepared for this card.

## Notes / caveats
- SV-11's run 1 was on the pre-incident XTX set; this one is on the changed set (HW-09). The served one-user figure on the changed set was 8.44 ms a token in FG-13's run, against 8.05 in SV-11, so a part of any difference is hardware.
- At 4 slots, 6 and 8 users never have all requests decoding at once, so no decode total is given for them (about 84 tok/s including prompt reading).
- Known issue of build 15, fixed in build 16 with `DS4_EC_FIX=1`: with the expert cache on, the number of experts streamed from host memory while reading a prompt grows by 8 with every prompt, so first-token time grows over a long-running server's life; restart the server periodically (HX-26). With the cache on, answers to the same greedy prompt can also change after a server has read many prompts (they read correct; the cause was expert picks summed twice, HX-28).

## Addendum (2026-11-14): four upstream correctness fixes, identity against build 15 (now in build 16)
- Four correctness fixes from upstream Strata (a router guard for all-NaN scores, an exit after a fatal GPU error, and two server fixes: an error-then-done drain and a control-line wait race) were ported onto build 15 in a later build. With build 15's identity harness and four helpers, all 8 single-process comparisons were stdout IDENTICAL (flags unset and as deployed × decode, drafter decode, batch test, plus 32K and 110K prompts, as deployed) and one served greedy user was IDENTICAL (1,025 token lines), with the same expert placement each pair (MEASURED, upstream-fixes-identity.txt). The fixes change no output on these workloads; they only act on the inputs they guard. They are in build 16, the build in this release (SV-16).
