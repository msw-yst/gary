# ME-15: Samplers beside a timed run change the run: one cost 21 % of four-user throughput
Status: method · Date: 2026-11-18
Code: no engine change. Monitoring and run harness only.

## What and why
- To find where host disk reads came from, a passive per-second sampler (process and cgroup I/O, per-thread walks) and a page-in sampler ran beside served A/Bs on 18 Nov. Later readings did not fit, and the samplers themselves were measured.

## Prediction
- None; the overhead was assumed small and not measured first. That was the mistake.

## Correctness
- Samplers change no output; they change timing.

## Timing
- 18 Nov, the test machine (4 × RX 7900 XTX + 4 × MI50, one EPYC Zen 2 16-core host); native MXFP4 pack, internal native build.

## Results
| sampler | effect | label |
|---|---|---|
| per-second process / cgroup I/O sampler with per-thread walks | inside the baseline arm itself, 4 users **79.0 → 62.6 tok/s** when it started; it had made a new build look 1.36× slower than the base with its switch off (FG-24) | MEASURED |
| page-in sampler | pinned to CPU 0, where the engine pins and busy-spins its decode lane thread, at about 62 % of a core; the same in every arm, so A/B ratios stood, absolute times and part of the arm-to-arm noise did not | MEASURED (cost) / INFERRED (pinning, from the source) |
| a lighter replacement (one process on the last core, no forks, I/O read every 60 s) | its pre-registered overhead pair failed: × 0.961 (one user) and × 0.956 (four users), in both directions, i.e. about 4 % run-to-run noise rather than a measured cost | MEASURED |
| the staging profiler used on 19 Nov (PF-15) | measured first: × 0.996–1.000 | MEASURED |

## Verdict
- **Rule:** no per-second sampler beside a timed served arm unless it runs identically in every arm and its overhead has been measured first; never on CPU 0 (the lane thread's core); the disk-read samplers of 18 Nov are withdrawn.
- The first two served A/Bs of that night (HX-36's first run; FG-23's store run) keep their ratios and lose their absolute times.

## Reproduce
- Run an A-against-A pair with and without the sampler, interleaved.

## Notes / caveats
- The mechanism of the 21 % loss is INFERRED: per-second cgroup statistics and per-thread directory walks under heavy memory reclaim.

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output) or INFERRED (our own reading).

Sources: no published data extract for this card; the run summaries are held privately.
