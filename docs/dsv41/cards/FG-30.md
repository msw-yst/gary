# FG-30: Moving the lead's join and routing onto a side stream (`DS4_LP_SIDE`): exact, but slower untraced; under a trace it looked faster
Status: dropped (no gain; flag default off, not merged) · Date: 2026-11-20
Code: not in the release commit of Gary, our fork of Strata (internal branch only). Flags: `DS4_LP_SIDE` bit 1 JOIN, bit 2 ROUTE (default off); switched per window with `DS4_AF_SCHED`.

## What and why
- At the MoE all-reduce the other three XTX wait ~110 µs a call for the lead (FG-29). In the attention-fix trace the lead's MoE stretch was 250 µs a layer against the members' 163 µs. The lead-only work there is the join of the MI50 helpers' and CPU lane's results (68.6 µs a layer, mostly waiting) and a slower routing launch (REPORTED, from the build notes).
- **JOIN** (bit 1) runs the join on a side stream right after routing, so the wait for the lane and helpers overlaps the lead's own shared and routed experts. **ROUTE** (bit 2) runs the lead's gate matvec and routing publish on a side stream, alongside its shared expert. Both are the same launches with the same inputs, so they are exact by construction; JOIN is also checked at load byte for byte.

## Prediction
- That overlapping the join and the routing would shorten the lead's MoE stretch and cut the members' wait. No numeric band recorded.

## Correctness
- Fixes on = off, 1,480 of 1,480 ids (MEASURED). Both features engaged (counters JOIN 24,960, ROUTE 25,600) (MEASURED).

## Timing
- 20–21 Nov, the test machine, 4 XTX + 5 MI50 helpers, the native MXFP4 pack on the stack build, frozen placement, 1 user 2K, greedy, drafter off. In-process ABBA. The follow-up ran the same four modes untraced, under a kernel trace (arm K), and under a kernel + HIP runtime trace (arm H).

- Every untraced block was slower in both halves of the ABBA (MEASURED).
- Under the trace: JOIN moved the 62 µs join off the main stream (the side ran 110–117 µs, 50 % overlapped) but added ~6.5 µs of event gaps and ~40 µs of other idle; ROUTE delayed the helper publish by 19 µs (66 → 85 µs), the MI50s' first matvec by 14 µs, and slowed the shared expert 28.7 → 37.3 µs by contention (MEASURED).

## Verdict
- **No-go: both side-stream changes are slower untraced (+5.8 % and +8.2 %),** and the members wait longer, not shorter.
- Under a kernel trace the result flips (JOIN and ROUTE each about −0.9 ms a token). The reading at the time was that a side stream costs host time and eats the host's run-ahead, so the host becomes the bottleneck only untraced. **That reading was tested and is wrong:** the host is never starved (FG-35). The slowdown is on the GPU and appears only untraced; for ROUTE it is the late publish to the MI50s (FG-31). With enough samples JOIN's cost shrank to +0.9 % (FG-31).
- The lead's lateness is mostly the CPU lane answering late, so the lever is placement (fewer CPU-lane experts), not scheduling (INFERRED; measured in FG-33).

## Reproduce
- Not reproducible from the release: the build is internal.

## Notes / caveats
- An earlier side-stream test measured +1.6 % slower, the same direction.
- Tracing slows the GPU about 15 % (INFERRED), which is enough to change which side of the GPU / host boundary is critical; timing conclusions here come from untraced arms only.
- One run each.

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output) or INFERRED (our own reading).
