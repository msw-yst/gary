# Prompt reading: two cycles (2026-11-21, data extract)

Sanitised extract of the runs behind [PREFILL.md](../PREFILL.md) and cards NX-10 to NX-12. Per-run engine logs and the kernel
trace are kept privately.

Server for both cycles: one card (XTX A + MI50 #1, #2 helper caches), MTP drafter with `STRATA_BATCH_MTP=1`, prompt cache on,
`STRATA_BATCH_SELF_COMMIT=1`, PARALLEL 4, calibrated Q4_K. Prompts: distinct slices of the engine's own source code (the same
prompts in every launch), temperature 0, presence_penalty 0, thinking off for the cold prompts; "50k" = 38-52k tokens. One
server at a time; MI50s at their high DPM state. Peaks XTX 57 C, MI50 58 C; no resets.

Workloads: c1 = one 52.2k-token prompt; c2 = 48.1k + 45.9k sent together; c4 = 38.3k / 47.7k / 47.3k / 51.2k sent together;
bg = a thinking-on stream of 2,500 tokens with a 44.7k cold prompt arriving 4 s in; 512 tokens out per cold prompt.

## Cycle 1: where the time goes (`STRATA_PREFILL_TIMING=1`)

Per 8,192-token chunk, mean of the full chunks of a 47.9k prompt; GPU timeline 7.6-8.0 s.

| Class | ms per chunk | share | per layer |
|---|---|---|---|
| experts: FP16 gate/up GEMM (`hipblasGemmEx`, default kernel) | 3,180 | 40 % | 66 ms (129 us per expert) |
| experts: dequant to FP16 | 635 | 8 % | 13 ms |
| experts: FP16 down GEMM (hipBLASLt solution 1147) | 663 | 8.4 % | 14 ms (27 us per expert) |
| experts: waiting for streamed blobs + host grouping + gather + combine | 330 | 4.2 % | 7 ms |
| attention, 12 layers | 1,170 -> 1,590 over the prompt | 15-20 % | 98-133 ms per layer |
| GDN, 36 layers | 880 | 11 % | 24 ms per layer |
| hyper-connection reads + writes | 400 | 5 % | 8 ms |
| PLE | 245 | 3 % | - |
| router + shared expert | 85 | 1 % | 2 ms |

Rates: 47.9k prompt 1,010 tok/s with the timing build, 1,062 untimed; 6.8k prompt 950-1,010 tok/s. XTX 95-100 % busy during a
read, ~265 W. MI50s and CPU pool idle during a read.

Kernel trace of one 6.8k read (traced 8.3 s vs 6.75 s untimed, same text): GPU busy 78 % of the read; the rest is ~128k short
gaps between per-expert kernels. The gate/up products run on rocBLAS FMA kernels (159 us and 70 us + a split-K fix-up, chosen
by row count) because the packaged hipBLASLt table had no row for N 1280 x K 2560.

Exactness rule here: every prompt read alone gives the baseline's text (4 x ~12k set 4/4, the 52k prompt in every launch). In
the baseline, a slot that decodes while another prompt is read is not exact: the read borrows 1,556 expert-cache slots, the
decoding slots compute those experts on the CPU path, which rounds differently. In the 4 x ~12k set sent at once, only the
prompt admitted last matched its alone text (1 of 4); the bg stream gave different texts in two baseline launches.

## Cycle 2: the tuned gate/up rows (the new reference) and exact decode beside a read

hipBLASLt offers 7 algorithms for f16-in / f32-out on gfx1100. The fastest per rows-per-expert M: solution 1145 (M <= 136),
1146 (137-200), 1147 (201+). Half of all experts have M <= 64 (mean 163), where 1145 takes 20-25 us against 1147's 38-40 and
the old kernel's 65-107. The packaged table `tools/hip/gfx1100-hipblaslt-100200.txt` carries these rows plus the down GEMM's
1145 at M <= 32 (bit-identical to 1147 there). `STRATA_PF_GU_LEGACY=1` restores the old kernel.

Numeric difference vs the old kernel: GEMM max |d| 8-9e-6 of the largest output; relative L2 against an FP64 product 7.9e-6
(matrix cores) vs 9.0e-7 (old FMA kernel). Decoded text first diverges at token 21 of 256; mean top-5 KL 3.0e-3 before it.

New reference text hashes: c1 solo 256 tokens `070fe3c6e2f04d97`, 512 tokens `54d84da205c99b75`; 4 x 12k alone
`9072faf0bf7b7b28 d3f46320436d34a9 4feaa39dc3339280 51d1d33197d37f9a`; the 2,500-token stream alone `90ba537bc76340d0`.

Batched FP16 conversion (`STRATA_PF_DQ_BATCH=G`, off): 0 of 505 experts differ, but TTFT +2.7 / +4.4 / +6.1 % at G 4 / 8 / 16.

Lent experts on the GPU (`STRATA_BATCH_LENT_GPU=1`): 4 x 12k sent at once == alone 16/16 in four launches (without the switch
1/4); ~97k lent experts per launch on the GPU, 0 on the CPU. The 2,500-token stream beside a read equals its alone text in 3 of
4 launches; the 4th flips at character 7,601, where the stream alone also flips once in 7 launches (a solo near-tie).
