# FG-12: A split indexer-score kernel: twice as fast at short context, slower at long; a length dispatch built
Status: kept (the dispatch passed its engine A/B and a four-helper re-check, and is in build 16, this release; the plain switch dropped at its bench gate) · Date: 2026-11-13 (addendum 2026-11-14)
Code: the dispatch is in the fork's release commit (build 16); the plain split switch is not. Flags: `DS4_IXSCORE_SPLIT` (bench only, dropped); `DS4_IXS_DISPATCH=<nmax>` (the split kernel only for one-row steps with at most `<nmax>` keys; code default off, `16384` in build 16's recommended environment).

## What and why
- The indexer's score kernel (one call in each of the 8 indexer layers per token, on the critical path) was cheaper to split across more workgroups at short context. The split kernel computes the same sums in the same order.
- It was timed on a kernel bench first (HX-23's lesson), at context lengths from 512 to 112,640 keys and at one and three rows.

## Prediction
- Bench, first run: new − old −4 to −22 µs a call at 1K keys (central −6), within ±10 % at 56K and 112K. Gate: new ≤ old − 4.0 µs at 1K, and no length worse than +2.0 µs. Pre-registered: yes, before the run.
- Cut-off bench (a second session): the length where the split stops winning between 16K and 48K, central 24–32K.
- The dispatch flag's engine A/B (pre-registered, before the run): B1 at a 64-token prompt −0.04 to −0.07 ms a token (central −0.05); 16K about −0.02; output identical. The band assumes 25–40 % of the raw 8 × −21.7 µs reaches decode.

## Correctness
- Bench: 56 exactness runs IDENTICAL (heads 32 and 24, one and three rows, every length); the old kernel's machine code in the bench was checked identical to the engine's (MEASURED). The cut-off session: 88 runs exact (REPORTED).
- The dispatch build: 112 of 113 existing kernels' machine code identical to build 14 (the one difference is a disassembler padding line), the split and old kernels identical to the benched ones, and the code-object size check passed (REPORTED from the build notes).
- Engine A/B (13 Nov): all 16 dispatch and placebo reps gave build 14's tokens (stdout IDENTICAL, same placement, the split kernel engaged on every XTX) at both prompt lengths (MEASURED, dispatch-ab.txt).

## Timing
- First bench: XTX #1 of the box, 400 iterations a cell, interleaved halves (13 Nov 12:23).
- Cut-off bench: a same-model RX 7900 XTX in another machine (stock voltage), the same bench and kernels.
- Engine A/B: 13 Nov 23:05, after the hardware change (HW-09); build 14 (OLD) against the dispatch build with `DS4_IXS_DISPATCH=16384` (NEW) and with the flag inert (placebo), 4 alternating reps each, drafter off, greedy, one session; a 64-token prompt (b1) and a ~16K prompt (b16). This run used five MI50 helpers, not production's four (see the notes).

## Verdict
- **The plain switch failed its gate:** −16.9 µs at 1K (twice the line) but +8.6 and +10.6 µs at 56K and 112K, against a +2.0 µs ceiling. Dropped.
- **Where it wins:** one-row steps at up to 16K keys; it loses from about 24K, and with three rows it already loses at 16K. The cut-off prediction was too optimistic (central 24–32K, measured 16K) and missed the row-count effect.
- **What was built instead:** `DS4_IXS_DISPATCH=<nmax>` uses the split kernel only for one-row steps with at most `<nmax>` keys; verify windows and long contexts keep the old kernel.
- **Engine A/B: PASS.** At a 64-token prompt it took 0.135 ms off a one-row token, 2.7 × the central prediction and beyond its range (−0.04 to −0.07), with the placebo at +0.004 and identical output. At ~16K it was −0.04 ms, inside the noise, as predicted. It was an adopt-candidate until a re-confirm in the production configuration (four helpers, with the next build's other changes); that is done (addendum), and the dispatch is in build 16.

## Reproduce
- No published run: the code is in the release commit (build 16); a scripted public re-run has not been prepared for this card.

## Notes / caveats
- The cut-off session ran on a different machine's card at stock voltage, so its absolute µs are not comparable with the first bench; the sign changes are.
- **The engine A/B ran with five MI50 helpers**, including MI50 #5 on its Gen1 riser: its device map came from build 14's tree, which predates the four-helper allowlist. Both arms had the same helpers and the change is XTX-only, so the A/B stands, but its absolute milliseconds are not production numbers. Other runs that night used the four production helpers.

## Addendum (2026-11-14): the dispatch re-checked with the four production helpers (then merged into build 16)
- In the same rotated rounds as fusion item 1 (FG-16), with the four-helper allowlist enforced: `DS4_IXS_DISPATCH=16384` **−0.165 ms a one-row token** (OFF 12.975 / IXS 12.810 ms; placebo −0.008), output identical to build 15; the five-helper run above had −0.135 (MEASURED; data in `data/cards/FG-16/`, fusion1-ab.txt). The re-confirm in the production configuration the verdict asked for is done; the dispatch then went into build 16, the build in this release (SV-16).
