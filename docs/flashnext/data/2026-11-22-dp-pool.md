## 3. Expert arenas on 2 MiB hugetlb pages

Host memory facts behind this [MEASURED]: 251.5 GiB total; the expert arena of our Q4_K file is 67.97 GiB (34,802 2 MiB
pages); the locked PLE table 26.9 GiB, counted once for two processes; each process ~10-12 GiB more at 4 slots. Two
private-arena servers leave 59-61 GiB available, the pool 108-126 GiB. Stalls of the kind in
[2026-11-21-dp-pool.md](2026-11-21-dp-pool.md) section 2: 2 in 16 private-arena cells, 0 in 28 pool cells.

The mechanism: a host range registered with the GPU (`hipHostRegister`) is a KFD userptr range. When the kernel moves or
unmaps one 4 KB page of it (reclaim, swap-out, compaction), KFD stops every queue of the process on every GPU until the
range is faulted back in. Nothing is printed in the kernel log; `/sys/class/kfd/kfd/proc/<pid>/stats_<gpu>/evicted_ms`
counts it. Hugetlb pages are never reclaimed, swapped or compacted. Every cell from here on records `evicted_ms` (maximum
over a process's devices) at load and at the end.

**Two private-arena servers** (one XTX + two MI50 each), MTP on, 4 slots; `vm.nr_hugepages=70000`:

|---|---|---|---|---|---|
| 4 KB pages + MADV_HUGEPAGE (unfixed) | 1 | **9.84 s / 14.87 s** | 0 / 0 | no | - |
| 2 MiB hugetlb | 4 | 0.069-2.629 s (mean 1.48 / 0.22) | 0 / 0 | no | 0.999-1.001 / 1.000 / 0.991 / 0.996 |

## 5. Quick checks

point after which the text only repeats. Two prompts run to 1,024 tokens in the ramp: one stops at end-of-sequence after 784

prompt-side MI50 option of this engine (`STRATA_PREFILL_HELPER_SOURCE`, a copy from a helper's VRAM, not compute) is armed

## 7. Run to run under concurrency with long prompts

Same agent-turn workload, the same arm run twice; (session, turn) texts compared.

| Arm | 4 agents | 8 | 16 | differences that start before a wrap-up re-send |
|---|---|---|---|---|
| cache on (section 6) | 23/24 | 32/48 | **73/96** | most (often cold first turns) |
| cache off (section 6) | 20/24 | - | - | - |
| + `STRATA_BATCH_DECODE_SHARE=0` (diagnostic: no decode during a read) | - | 47/48 | - | 0 |
| + `STRATA_BATCH_LENT_EXACT=1` (serial reads) | - | 47/48 | 89/96 | 0 |
| + `STRATA_BATCH_LENT_EXACT=1 STRATA_BATCH_CONCURRENT_READ=2` | 23/24 | 45/48 | (stopped) | 0 |
| + `STRATA_BATCH_LENT_EXACT=1 STRATA_REUSE_CKPT_ONLY=1` | - | 41/48 | (stopped) | 6 of 7 |
| + `STRATA_BATCH_LENT_EXACT=1 STRATA_PARALLEL_SLOTS_ONLY=1` | 23/24 | 46/48 | 91/96 | 0 |
| **+ `STRATA_BATCH_LENT_EXACT=1 STRATA_PARALLEL_SLOTS_ONLY=1 STRATA_REUSE_CKPT_ONLY=1`** | **24/24** | **48/48** | **96/96** | - |

- Cause 1 (the large one): with `--batch` a prompt read lends 1,556 of the XTX's hot expert slots to the prompt path. A
  decode window that runs between the read's parts saw those experts as missing and computed them on the CPU, which rounds
  differently. Whether a step landed there depends on timing. With decode share 0 the runs agree; with
  `STRATA_BATCH_LENT_EXACT=1` the lent experts run on the GPU from the arena's device alias and the engine counts the CPU's
  share: **0 lent experts on the CPU in every log** (for example 99,256 / 85,171 on the GPU).
- Cause 2 (the remaining differences, all 24-139 characters after a wrap-up): when a thinking turn reaches its reasoning
  budget, the server ends the reasoning with a short wrap-up and sends the request again. That re-send continued either from
  the old slot's live end or from the parked conversation, depending on which of two server events arrived first. Solo
  <-> slot hand-offs of timing-dependent length are a second form of the same thing. `STRATA_PARALLEL_SLOTS_ONLY=1` (every
  request decodes in a batch slot) plus `STRATA_REUSE_CKPT_ONLY=1` (continue only from checkpoints) removes both. Either
  alone does not.
- With the last row, texts still differ from the default configuration's where a wrap-up's read start moved (44/48, 88/96
  against slots-only alone): deterministic, but other bits.
- A decode-share-0 control of the conversation-cache path with drafter holes (16 agents): MTP on vs off 94/96, both
  differences after a wrap-up; 53-54 holes filled per worker. Filling a drafter's hole before a park changes no output.
- The gates in every one of these cells passed: their prompts are ~30 tokens and are read through the decode windows, so
  they borrow no slots and cannot see cause 1.
