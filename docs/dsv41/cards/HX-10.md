# HX-10: Helper round trip: overlap the down rows, packed staging (A, B)
Status: kept · Date: 2026-11-10
Code: in Gary's release commit. Flags: `DS4_HELPER_OVERLAP=1` (A), `DS4_HELPER_BATCH=1` (B); default off.

## What and why
- A: start the down-projection rows' return while the rest of the helper window runs. B: pack the staging buffers so one copy moves a window.
- Target slice: the lead's helper wait: ~3.1 ms of a 16.9 ms B1 step on tp4h4 [M, `timing.txt` helper column].

## Prediction
- Desk estimates in the helper-overhead design note: several hundred µs per token at B1.
- Pre-registered: yes (design note committed before the run).
- Gate: every identity pair IDENTICAL or the run stops.

## Correctness
- Decode, batch test (B1/2/8) and teacher-forced score, flags vs off, tp3h3 and tp4h4: all IDENTICAL (MEASURED).

## Timing
- Hardware: 4 × RX 7900 XTX (XTX #1–3 Gen4 x16, XTX #4 Gen4 x8) + 4 × MI50 32 GB at 135 W (Gen4 x4 each). XTX at minimum power cap with −50 mV. MI50 DPM `auto`.
- Software: ROCm 7.14 on Linux; Strata v0.2.9 plus Gary's changes. Kernel version: not captured in the published extracts.
- Workload: private 1,024-token prompts, B1/B2/B8, N 256, expert cache off.
- 3 reps, interleaved, fresh process per arm. MI50 DPM `auto`.

## Verdict
- Exact and a small win at B1 (−1.8 … −3.1 %); nothing measurable at B8, where process-to-process spread is ±15 %. The helper-wait column barely moved, i.e. the time did not come off the wait the change targeted (MEASURED). Kept as the base for HX-17.
