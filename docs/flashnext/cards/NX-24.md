# NX-24: Run-to-run identical agent turns: every request in a batch slot, continue only from checkpoints
Status: kept (opt-in; the configuration for reproducible runs, not the speed default) · Date: 2026-11-22
Code: both switches are opt-in, off by default ([Settings](../README.md#settings)). Flags: `STRATA_PARALLEL_SLOTS_ONLY=1` (server, with `--batch`; implies `STRATA_PARALLEL_SOLO=0`), `STRATA_REUSE_CKPT_ONLY=1` (engine), with `STRATA_BATCH_LENT_EXACT=1` ([NX-23](NX-23.md)).

## What and why
- With the lent experts on the GPU, agent turns were 47/48 and 89/96 identical between two runs; every difference started just after a thinking-budget wrap-up re-send (the server ends a thinking turn's reasoning at its budget with a short wrap-up and sends the request again).
- The cause: the re-send continued either from the old batch slot's live end or from the parked copy of the conversation, depending on which of two server events arrived first; and requests moved between the solo path and a slot at timing-dependent points, which leaves a live end at a timing-dependent place. A continuation read from a different start reads other chunks, so other bits.
- `STRATA_PARALLEL_SLOTS_ONLY=1`: with `--batch` every request is admitted into a batch slot and decodes there to its end, never on the solo path. `STRATA_REUSE_CKPT_ONLY=1`: an idle slot's end and a parked conversation's live end are not reuse sources, only checkpoints (at turn boundaries or on the read's grid, the same in every run).

## Prediction
- Pre-registered: yes, for both steps. Bar: 100 % identical at 4, 8 and 16 agents (24/24, 48/48, 96/96); 0 lent experts on the CPU; agent turns at 4 agents and steady 4+4 >= 0.98x the default.
- `STRATA_REUSE_CKPT_ONLY=1` alone (before slots-only) was tried first and made it worse: 41/48, because solo hand-offs put checkpoints at timing-dependent places.

## Correctness
- **Slots only + checkpoint-only reuse + lent experts exact: 24/24, 48/48 and 96/96 turns identical between two runs**, including every wrap-up turn; 0 lent experts on the CPU; 0 solo legs (MEASURED).
- Slots only alone: 23/24, 46/48, 91/96 (MEASURED).
- Gates passed; steady texts identical to the default's. Agent-turn texts differ from the default configuration's where a wrap-up's read start moved (44/48, 88/96 against slots-only alone): reproducible, but other bits (MEASURED).

## Timing
- Hardware: 2 × RX 7900 XTX 24 GB (272 W cap), 4 × Instinct MI50 16 GB (135 W cap), EPYC 7642 (48 cores), 256 GB DDR4-2666.
- Workload: NX-22's configuration, prompt cache on, `STRATA_BATCH_LENT_EXACT=1`; steady 2+2 and 4+4, agent turns at 4, 8, 16 agents; 2 runs per arm.

## Verdict
- Kept as the reproducible-run configuration (A/Bs, regression gates): run-to-run identical agent turns at every level measured.
- Not the speed default: steady multi-user decode costs ~5 % (4+4 0.944x, slowest 0.932x; 2+2 0.959x). The cost comes from the slots-only half; its cause is not measured (candidates: a lone request in a slot verifies one MTP proposal a window instead of the solo path's wider windows; every admission copies its state into a slot) (INFERRED).
- An untested alternative that might keep the steady speed: keep the solo path, and make a wrap-up re-send wait for the old slot's release and go back to that slot.

## Reproduce
- "Layout 3" in [README.md](../README.md#launch) with `STRATA_BATCH_LENT_EXACT=1 STRATA_REUSE_CKPT_ONLY=1` on the engine and `STRATA_PARALLEL_SLOTS_ONLY=1` for the server; the server logs "STRATA_PARALLEL_SLOTS_ONLY=1: every request decodes in a batch slot, never on the solo path".

## Notes / caveats
- Identical from run to run, not identical to the default configuration's texts: checkpoint-only reuse changes where a wrap-up's continuation is read from.
- Absolute numbers come from our own agent sessions and a private prompt set; ratios between arms of the same run are the comparable quantity.

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output), ESTIMATE (our arithmetic) or INFERRED (our own reading).
