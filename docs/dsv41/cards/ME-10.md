# ME-10: Every benchmarked build is in git, and rebuilds byte for byte
Status: method · Date: 2026-11-13
Code: Gary's internal history (one branch and one tag a build). Flags: none.

## What and why
- After build 12, builds were made from working trees and plain copies, recorded only as diffs and checksums. On 13 Nov every build since build 12 (nine of them, from the build-12 merge base through build 14 and its three side builds) was committed as its own branch, with a tag on the source commit carrying the benchmarked binary's sha256, plus a records commit; the history was pushed to an off-box remote. Every saved hand-made diff agreed with git, and a repository integrity check was clean (REPORTED from the lineage report).
- A history only matters if it regenerates what was measured. So each tag was then rebuilt from `git archive` with its own recipe and compared with the benchmarked binary.

## Prediction
- None recorded.

## Correctness
- This card is itself the correctness check of the build provenance.

## Timing
- The rebuild ran on another machine's CPU (no compiler on the GPU box), in containers with the same image as the original builds and the original in-container paths, 13 Nov 15:43–16:34.

## Results
| item | value | label |
|---|---|---|
| tags rebuilt | 9 of 9 byte-identical to the benchmarked binaries | MEASURED (the check's own report) |
| straight from the archive | 4 (build 14 and its three side builds) | MEASURED |
| needing the original build-id string | 5: without it, 2 bytes of the `--version` string differ in one object file; disassembly and every GPU code object identical | MEASURED |
| not recovered | one older server build edited after it was built, and about ten experiment trees whose build-time state is unknown | REPORTED |

## Verdict
- **The git history now regenerates every engine benchmarked since build 12, byte for byte.** Every card from 12 Nov on names a build that can be rebuilt.
- Rule from now: commit and tag every build before it compiles, and stamp it with its own tag commit as the build id, so `--version` tells builds apart.

## Reproduce
- Check out a build's tag, write its build id to `BUILD_ID` in the source root, and run its recipe; compare the binary's sha256 with the tag's.
