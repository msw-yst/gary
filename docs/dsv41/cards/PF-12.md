# PF-12: MI50 prompt tiles (`DS4_PF_TILE`): bit-exact, time to first token −15 % at every length
Status: kept (build 15) · Date: 2026-11-13
Code: in the fork's release commit. Flags: `DS4_PF_TILE=1` (default off; on in build 15's environment, with `DS4_PF_HELPER=8192`).

## What and why
- With the prompt helper on (PF-11), the MI50s compute the experts they hold for each prompt chunk. The engine's own counters on build 12pf showed the members waiting for their helpers for 17–22 % of prompt wall time: 594–705 ms of a 3,828-token prompt's 3,205 ms, 335–445 ms of 2,053 ms at 1,927 tokens, 193–252 ms of 1,207 ms at 1,007 tokens (REPORTED from the engine lines read at the time). So the helper's prompt work is on the critical path.
- The helper's prompt expert sets ran the decode-style int8 kernels at up to 16 rows an expert a round. A one-pass tiled kernel for those sets was written, benched on the bench MI50 (MI50 #5, HW-10), and then ported to the engine.

## Prediction
- Bench v1: new ≤ 0.70 × old on the primary 8K cell (IQ2_XXS), no cell worse than +5 %. v2 and v3 kept the same lines on fresh cells and seeds; v3: type-mix-weighted 8K ≤ 0.75, every 8K cell ≤ 0.85, no cell > 1.03. Pre-registered: yes, each version before its run.
- Engine: 8K time to first token 5–8 % faster (gate ≤ 0.93 × off); placebo within ±3 %; decode no worse than × 1.005. Pre-registered: yes, before the run.

## Correctness
- Bench: every version bit-identical to the old round path in every cell, outliers and edge cells included (MEASURED, verdict lines in the extract).
- Engine: served greedy output with the flag on IDENTICAL to off, 1,025 token lines; unset IDENTICAL to build 14 (MEASURED). Both identity pairs listed the bench MI50 among the helper devices, on both sides; the timing arms used the four production MI50s.
- Batched-vs-solo identity was not exercised in this run (the prompt helper already makes it non-invariant, SV-10).

## Timing
- Bench: MI50 #5 alone, 13 Nov 00:12–07:23 (v3 full run after its cooling fix).
- Engine: 13 Nov 10:41, pre-incident hardware (4 × RX 7900 XTX: XTX #1–3 Gen4 x16, XTX #4 Gen4 x8; 4 × MI50 32 GB at 135 W, Gen4 x4; XTX at minimum power cap with −50 mV; MI50 DPM `high`). Build 14 plus the flag; served deploy environment, PAR 8; OFF / ON / placebo, 3 rounds.

## Verdict
- **Time to first token −15 % at 2K, 8K, 32K and with 4 users, bit-exact, decode unchanged.** About twice the central prediction: the MI50's share of prompt time was larger than modelled [I]. Kept; on in build 15.
- **The bench taught the right kernel shape.** v1 assumed the sets were bound by re-reading weights; they are bound by arithmetic and x traffic (re-reads cost ~3.7 of 43 ms). v2's fix (several outputs a lane share each x load) worked on some types and not others, and lost on small chunks; v3 dispatches per type and falls back to the old path for small sets [I from the bench cells].

## Reproduce
- No published run: the code is in the release commit; a scripted public re-run has not been prepared for this card.

## Notes / caveats
- The engine port first failed the code-object size check: it would have grown an XTX code object by one 2 MiB piece (QA-08). The fix compiled the new kernels for gfx906 only; the XTX code objects are unchanged.
- The bench MI50 reached 81 °C in the v2 and v3 runs and stopped two main-queue jobs through the shared thermal watcher before it got its own fan curve (HW-10).
