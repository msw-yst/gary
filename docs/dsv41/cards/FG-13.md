# FG-13: A faster XTX down-projection kernel (`DS4_DN_TPB`): −20 % on the bench, nothing in the engine
Status: dropped (no gain; the flag stays in the code, default off) · Date: 2026-11-13
Code: not in the fork's release commit (internal branch only). Flags: `DS4_DN_TPB=0/2/4` (default 0 = today's kernel).

## What and why
- The XTX's routed-expert down projection reads cold weights each token. A kernel bench of tile shapes (2, 4 or 8 tiles a block, a two-entry variant and a persistent variant) looked for a faster exact form.
- The best bench arm went into the engine in its own source file (the existing one had only 12,911 bytes of code-object headroom, QA-08), covering both the one-row and the window launches.

## Prediction
- Bench: the 4-tile arm about −3 µs a call. Pre-registered: yes.
- Engine, single session (B1): 4-tile − old 0 to −0.12 ms a token (central −0.08); the floor 0 if the down projection is off the critical path. Gate: ≤ −0.03 ms and beyond the rep spread. Served decode (secondary): 0 to −0.15 ms a token at one user (central −0.07). Pre-registered: yes, before the engine run.

## Correctness
- Bench: no differing cell in any arm (REPORTED). Engine: output IDENTICAL to old in every rep of every arm (MEASURED); the 120 old kernels' machine code identical to build 14 and the 8 new kernels identical to the benched ones (REPORTED from the build notes).

## Timing
- Bench: a same-model RX 7900 XTX in another machine at stock voltage, 184 cells × 7 arms × 200 iterations.
- Engine: this box after the 13 Nov hardware change (HW-09). B1: 64-token prompt, drafter off, greedy, 256 tokens, 4 reps an arm alternating. Served decode: 3 rounds, one and four users.

## Verdict
- **No gain in the engine.** B1 +0.026 ms (not separable), served decode unchanged at one user; at four users the placebo drifted as much as the arms. The bench win is real in isolation, but the down projection is not on the decode critical path at these batch sizes [I].
- The bench beat its own prediction 3.9× (−11.76 against −3 µs) and the engine then showed nothing: a large kernel gain says nothing about the token until the kernel is shown to be on the path.
- The code stays, default off, in case much larger verify windows become normal.

## Reproduce
- No published run: the code is not in the release commit yet.

## Notes / caveats
- The served one-user figure (8.44 ms) is on the changed XTX set and is not comparable with SV-11's 8.05 ms.
