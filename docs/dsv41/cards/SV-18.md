# SV-18: STACK: the four prompt-path fixes and a fifth helper together against native production: first token 2K 15.9 → 2.9 s, a 30-minute soak with 0 errors
Status: kept (GO; the release-candidate configuration for the native pack; internal native build, not in a release) · Date: 2026-11-20
Code: not in the release commit of Gary, our fork of Strata (internal branch only). Flags (branch-only, each default off): `DS4_STORE_DIRECT=1` (PF-20), `DS4_RA_STORE_SKIP=1`, `DS4_PF_HELPER_PACK=1`, `DS4_STORE_UNHELD=1` (PF-19), with `DS4_PF_HELPER=8192 DS4_PF_HELPER_ROOM=1`; five MI50 helpers (HX-37).

## What and why
- Every change that passed its own gate on 19–20 Nov, combined and measured once against the native production configuration, plus a mixed-load soak: the RAM store holds only what the XTXs must stream, the stream keeps its batches full, read-ahead skips experts the store holds, the XTXs DMA straight from the store, and a fifth MI50 helper.
- Left out because they had not passed yet: the MI50 multi-token kernel (HX-38), selective block 6 (DR-14) and the 256 cutoff (PF-21).

## Prediction
- Pre-registered: one-user decode, four-user throughput and first token at 2K / 8K / 14K each no worse than production (with bands); text closeness; drift 0.93–1.07; a 30-minute mixed soak with 0 errors, no memory-error count change, and temperature limits.

## Correctness
- Text closeness, S1 against P1: 4 of 4 close. With `DS4_CACHE_DET=1`, S1 = S2 on 10 of 10 cells (MEASURED).
- Memory error counters (EDAC) 0 corrected / 0 uncorrected before and after the soak; also 0 / 0 at three independent reads during it (MEASURED).

## Timing
- 20 Nov, the test machine: 4 × RX 7900 XTX (tensor-parallel 4) and MI50 32 GB helpers at 135 W (P: production, four helpers; S: STACK, five); one EPYC Zen 2 16-core host, DDR4 at 2933. Native MXFP4 pack. Order P1 S1 S2 P2, then the soak on S. Locked placement in the timed arms (ME-16).

## Verdict
- **GO.** Every timed bar passes and the soak is clean: on the native pack a 2K prompt's first token is 5.4× faster than production, one-user decode 20 % faster and four users 13 % more.
- **The summary script first printed NO-GO (soak).** Its parser read the memory-error file's labels ("ce", "ue") where the values should be, failed to convert them, and reported "no reading", which the soak gate treats as a failure. The raw file reads 0 / 0 before and after. With the parser fixed and the same run re-summarised (no new GPU time), the verdict is GO. We record both, because the first verdict was wrong for a reason that had nothing to do with the machine.
- These are locked-placement numbers. As served, with a live cache, decode is faster still and the 2K first token about 0.7 s slower (SV-20, ME-16).
