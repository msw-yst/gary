# HX-29: Why one user got slower on build 16: the expert-cache fix stops the cache's promotion
Status: explained (the cause of build 16's served one-user slowdown) · Date: 2026-11-14
Code: no new code. The run switches `DS4_EC_FIX=1` (HX-28, in this release) on and off in build 16's recommended environment.

## What and why
- Served on the same day, build 16 was 5.3 % (2K) and 8.7 % (8K) slower per token than build 15 for one user, and 14.8 % slower on the 8K first token (SV-16). In one process its five changes are 0.44 ms a token faster, so the loss had to come from serving.
- Hypothesis: build 15's expert cache moved hot MI50-held experts into XTX memory after each prompt read. That made the following decode faster, and it also caused the double count of HX-28. `DS4_EC_FIX=1` stops those moves, so it gives the speed back along with the bug.
- Test: one build 16 server binary, run with build 16's environment and with the same environment minus `DS4_EC_FIX=1`, nothing else changed.

## Prediction
- Without the fix: one user 2K −0.42 ms a token (−0.60 to −0.25), 8K −0.76 ms (−1.0 to −0.5), 8K first token −13 % (−17 to −8). Pre-registered: yes, before the run.

## Correctness
- Not an identity test. Greedy output with and without the fix differs from line 64 of 130, as expected: without the fix the double count changes the sums (HX-28) (MEASURED, report-only).
- The run's checks confirmed that the two arms differ only in `DS4_EC_FIX=1` and that each server ran its arm's environment (MEASURED).

## Timing
- 14 Nov, 4 × RX 7900 XTX + 4 × MI50 at 135 W. Served, 4 slots, sampled requests, drafter on. Rounds with, without, without, with (one server each), so drift shows as a difference between the first and last round.
- Each round also ran a short single-slot probe with the cache on and verbose output, to count the cache's moves after each prompt.

## Verdict
- **Explained: the cache fix is what slowed one user down.** All three predictions came in, each far outside the spread between rounds.
- With the fix on, the cache makes no moves after a prompt. Build 15's single-user speed came from those moves.
- **The fix stays.** Without it batched output is wrong (HX-28). The follow-up keeps the moves and counts each pick once (HX-30).

## Reproduce
- No published run: the served benchmark client is not published. The switch is in this release; set or unset `DS4_EC_FIX=1` in build 16's recommended environment.

## Notes / caveats
- The decode gain without the fix is partly from the wrong sum, not only from real work saved: HX-30 recovered the prompt-time loss but little of the decode loss [I].
