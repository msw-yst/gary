# FG-14: A rewritten XTX gate/up kernel: a bench promise that came from a mis-compiled baseline
Status: dropped · Date: 2026-11-13
Code: not in Gary's release commit (bench only). Flags: none in the engine.

## What and why
- A rewrite of the XTX routed-expert gate/up kernel (three variants) looked faster on a first bench. The plan was a bench, then an engine port.

## Prediction
- About −3.0 µs a call (−1.5 to −5); gate ≤ −3.0 µs and no cell worse than +1.0. In the engine about −0.02 ms a token at best. Pre-registered: yes.

## Correctness
- The first run was refused by its own machine-code gate: the bench's copy of the old kernel compiled to the engine's code for one instantiation (495 instructions, identical) but not for the other (494 against 502), so a win could not be claimed about the engine (REPORTED).
- The second run used a baseline whose machine code was identical to build 14's for both instantiations; every mode was exact in every cell, 144 runs a cell (REPORTED).

## Timing
- A same-model RX 7900 XTX in another machine at stock voltage.

IQ2_XXS and IQ2_XS, n_ff 512 and 768.

## Verdict
- **Slower in every cell once the baseline is the engine's real kernel.** The earlier promise came from comparing against a baseline the compiler had built differently. Dropped.
- Also learned: adding a kernel to the engine's main expert source file changed how the compiler built an existing instantiation, so any future port there needs a machine-code identity check on the old kernels too.

## Reproduce
- No published run: bench only.

## Notes / caveats
- The new kernels were also 40,964 bytes against 12,911 bytes of headroom in that source file's code object, so a port could have carried only about a third of them (QA-08).
