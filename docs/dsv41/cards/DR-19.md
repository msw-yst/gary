# DR-19: A GPU-chained drafter round (`DS4_CHAIN`): shelved before it was built, because its gain was below the A/B noise
Status: shelved (designed, not built; revivable now that in-process noise is lower) · Date: 2026-11-18
Code: none (desk study; a design and an empty branch from the native build, never committed). Flags: `DS4_CHAIN` (designed, does not exist in any build).

## What and why
- With the drafter on, each round goes through the host: the verify pass, then sampler + copy to host + host sync, then the host computes what was kept, rolls back the rings, seeds the drafter (copying each drafter block's ring from the lead through pinned host memory to every member), and launches the next draft. A kernel trace of the native build showed holes between the sampler and the next drafter launch.
- The idea: keep the round on the GPUs (accept on device, seed by peer copies, spin on a mapped mailbox), exact by construction. Phase A was the mailbox, on-device accept and peer seeding.

## Prediction
- First estimate: −1.0 to −2.5 ms a one-user step, exact; later −1.0 to −3.0 ms (2.5–7 %) from trace means (INFERRED, desk).
- Re-cut by step **medians** before building (the means were inflated by a few 30–40 ms request-boundary steps): Phase A could remove 0.45–1.0 ms traced, **0.35–0.8 ms untraced (0.8–1.9 % of a ~42 ms native verify step)**; all of the change ≤ ~1.2 ms (≤ 3 %) (INFERRED from trace medians). Pre-registered: the gate was one user ≤ 0.98×.

## Correctness
- Not run (not built).

## Timing
- Desk, 17–18 Nov, from a kernel trace of the served native build (one user, 2K and 8K, 4 slots, drafting limit 3).

## Verdict
- **Shelved (decision, 18 Nov): the whole change is ≤ ~3 % of a one-user step, below what the served A/B could resolve (~4 %).** Phase A was predicted to land under its gate and inside the noise.
- A cheaper check had already pointed the same way: batched GPU sampling removed one or two sampler syncs a one-user step and gained nothing measurable (FG-24).
- In-process A/B noise is now ~0.15 ms a token (ME-17's stage-timing runs), so a 0.35–1.2 ms effect would now be resolvable; the item stays revivable.
