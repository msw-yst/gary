# HW-18: The freeze fix: lock the RAM store's pages (`DS4_STORE_MLOCK`): evictions while serving fall to ~0, no cost
Status: kept (host setting permanent from 22 Nov; locked store on by default in release candidate rc2, its gate pending) · Date: 2026-11-22
Code: not in the release commit of Gary, our fork of Strata (internal branch only, on release candidate r2a; the second release candidate, SV-27, turns the lock on by default when the store is registered and refuses to start without it). Flags: `DS4_STORE_MLOCK=1`, `DS4_STORE_HUGE=1` (default off on the first branch); host: `vm.compact_unevictable_allowed=0`, container memlock limit unlimited; for the huge-page arm, 103,503 reserved 2 MiB pages.

## What and why
- HW-17: the registered RAM store's movable pages make the GPU driver stop every queue. Two ways to make the store unmovable without unregistering it:
  - **L:** mlock each 1.2 GB store chunk before registering it, and tell compaction to leave locked pages alone.
  - **H:** back the store with 2 MiB huge pages (103,500 pages for 217.1 GB).
- If a lock or huge-page map is refused, the build logs it and falls back to today's behaviour. Only the page backing changes; slot sizes, offsets and registration are unchanged.

## Prediction
- Pre-registered: yes. Bar: eviction time at the unregistered level (HW-17: 1–2 s per device); no-harm bars on decode and first token (H: first token ≤ 11.0 s).

## Correctness
- Token ids equal across all arms; store slots the same (11,520) (MEASURED).

## Timing
- 22 Nov, the test machine (four XTX + five MI50), release candidate r2a's environment, store registered (217.1 GB), native MXFP4 pack. Order R1 L1 H1 H2 L2 R2; host settings set per arm by a root helper and restored afterwards.

## Verdict
- **Locking the store works: evictions fall ~90 % overall and to ~0 once serving, with no decode or first-token cost.** By its strict bar (unregistered level over the whole life, load included) it reads PARTIAL; while serving it meets it.
- Huge pages cut evictions less (1.8 s after ready in one start) and slowed one first token past its bar, but loaded 3 minutes faster. Load time is mostly the cost of registering, not eviction (L loads no faster) (INFERRED). A lock plus huge pages, or a faster registration path, is a later option.
- Decision (22 Nov): make it permanent. The compaction setting is applied at every boot; the engine's next release candidate locks the store by default and refuses to start if it cannot.

## Notes / caveats
- No soak was run: the decode-freeze rate (6 of 30 processes, HW-17) needs ~30 processes to show a change; eviction time is the measure used here.
- The served container needs an unlimited memlock limit, or the lock is refused.
