# HX-34: The MI50 helper's request round trip, stage by stage: 104.6 µs today, 68.9 µs with graph replay and zero-copy
Status: finding · Date: 2026-11-16
Code: in Gary's release commit (release 3). `ds4_helper_rt_bench` (`tests/dsv41/helper_rt_bench.cpp`, already in release 2) drives the helper's request path on one MI50 with the engine's own buffers and kernels; `tools/qbench/run-card.sh` phase `rt` runs the set below. The faster variants are bench modes only, not engine switches.

## What and why
- HX-33 times the expert kernels alone. What the lead XTX waits for is a whole helper request: plan and input copied to the MI50, the expert kernels, the output copied back, and the wait for completion. This splits that round trip by leaving out or replacing one stage at a time.

## Prediction
- Pre-registered: the fixed round trip is 90–130 µs.

## Correctness
- Every variant that changes how data moves (a different copy engine, zero-copy, kernel-side fetch, graph replay) was checked against the baseline's output: all BITWISE identical (MEASURED). Ablation rows leave a stage out and are timing only.

## Timing
- 16 Nov 14:19 UTC, the same MI50 and machine as HX-33, one expert per request (40 layers × 6 experts = 2.17 GiB of expert blobs, rotated), T = 1 token, 2,000 requests a cell; p50 / mean / p90 of the round trip seen by the requesting thread.

## Results
`--sweep 1`, selected rows; every row, including the spin-wait and zero-copy-input variants, is in the data file (MEASURED):

## Verdict
- **The prediction held:** 104.6 µs, inside 90–130.
- **About 60 % of the round trip is the expert kernels (63 µs); the rest is moving data and waiting.** Without kernels a request still costs about 40 µs; without the copy engine either, 15 µs.
- **Graph replay with kernel-side input fetch, zero-copy output and a flag wait cuts the round trip by 34 % (104.6 → 68.9 µs), output bitwise identical.** Not built into the engine yet.
- Leaving out one copy does not save its share: dropping the x or the output copy made the round trip slower (128–133 µs). The stages overlap and share queues, so they are not additive (INFERRED).
- An idle MI50 answers about 32 µs slower (136.5 against 104.7), consistent with power-state wake-up between layers (INFERRED; not measured here).
- A second expert in the same request costs about 60 µs, roughly its kernel time: batching more picks per request amortises the fixed cost (INFERRED).

## Reproduce
- `tools/qbench/run-card.sh OUT rt` on one MI50 (`HIP_VISIBLE_DEVICES` pinned), with `QB_BIN` pointing at the `ds4_helper_rt_bench` build.

## Notes / caveats
- One MI50, one run. The PCIe link configuration of the test machine was not re-measured for this run.
- The run's "empty request" cell passed `--empty` without its value, so it ran as a repeat of the baseline (104.1 µs); the floor is the sweep's "event only" row. `run-card.sh` now passes `--empty 1`.
