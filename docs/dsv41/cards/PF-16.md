# PF-16: Fewer bytes read is not a faster prompt: reading each expert once, and skipping read-ahead for RAM-held experts
Status: dropped (read-once: no gain twice; read-ahead skip alone: storage reads down, first token not faster on its own) · Date: 2026-11-18 (second read-once run 2026-11-18 night)
Code: not in the release commit of Gary, our fork of Strata (internal branch only). Flags: `DS4_PF_ONCE=1` (each expert read once per chunk and shared by the four members), `DS4_RA_SKIP_RESIDENT=1` (read-ahead leaves out experts the RAM store holds) (both branch-only, default off). A later form of the second, `DS4_RA_STORE_SKIP`, is part of PF-19 and PF-20.

## What and why
- PF-15 found that each tensor-parallel member reads a whole expert and keeps a quarter, so a prompt pass reads about four times the bytes it needs, and that read-ahead asks for file pages of experts that are already in RAM. Two cheap, exact changes followed: read each expert once and share it, and skip read-ahead for RAM-held experts.

## Prediction
- Read-once: storage reads per 2K prompt 58 → 15–20 GB and first token × 0.4–0.6 if the reads were the bound; GO at ≤ 0.85.
- Read-ahead skip: first token × 0.65–0.90 (GO at ≤ 0.85); storage reads × 0.60–0.80.

## Correctness
- Read-once: bits PASS 6 of 6 (first run) and IDENTICAL short and long, equal placement (second run) (MEASURED).
- Read-ahead skip: bits PASS (MEASURED).

## Timing
- 18 Nov, the test machine: 4 × RX 7900 XTX (tensor-parallel 4) and 4 × MI50 32 GB helpers at 135 W; native MXFP4 pack, internal native build, one user, 2K prompts. Arms interleaved (O R R O or O L R R2 L2 O2).

## Verdict
- **Both dropped as they stood.** Read-once removed three quarters of the `read()` bytes, but those were page-cache hits: the disk bytes and the first token did not move. Skipping read-ahead for RAM-held experts removed about 30 % of the storage reads, but the first token did not get faster, and decode looked slower.
- What binds the read is the host copying itself, the same volume whichever way it is read (PF-15). The work had to leave the host copy path: PF-19 (the MI50s take their own experts, the store keeps the rest, full batches) and PF-20 (DMA from the store).
- One day later the read-ahead skip, on the newer build and alone, cut the first token by about 20 % but cost 2.5 % decode (PF-20, its Q arm). Why the two runs differ is not known.

## Notes / caveats
- The first read-once run's baseline arms drifted 11 % between themselves, so its first-token ratio is inconclusive by its own rule; the second run was clean (drift in band, placement equal).
