# FN-03: Qwen3.8-Flash-Next: 1 XTX + 1 MI50 helper + MTP
Status: kept (best measured layout) · Date: 2026-11-10
Code: harness branch on build 10's engine (engine source unmodified); inclusion in the release commit to be confirmed in the rename / build phase. Flags: `--helper-device`, MTP on, `--pipeline-windows 2` (arm d).

## What and why
- Model: ISTA-DASLab Qwen3.8-Flash-Next 512-expert IQ3_S, every expert resident in VRAM. Arms: a = XTX #1 + MI50 #1 helper; b = layer split over XTX #1–3; c = b + MTP; d = c + `--pipeline-windows 2`; e = a + MTP.
- Target slice: tokens per decode window (1.29 → ~2.7) at a modest cost in window time.

## Prediction
- MTP gives +45–70 % at B1, to about 85–100 tok/s.
- Pre-registered: yes (FN-02 plan).
- Abort: a split decode window more than 10 % slower than baseline means the split is for prompts only.

## Correctness
- Teacher-forced over 511 positions, against arm a: b and e top-1 100 %, KL 0; c 99.61 %; d 98.04 % (MEASURED).
- This covers the prompt path only. Decoded output of e differs from a on 7 of 8 prompts; e is deterministic across reps [M, `agree.tsv`, prompt ids only]. The decoded quality of MTP is untested.

## Timing
- Hardware: After a full power cycle with new PSUs. XTX #1–3 + MI50 #1 at 135 W; peaks XTX 80 °C, MI50 49 °C.
- Software: ROCm 7.14 on Linux; Strata v0.2.9 plus this fork's changes. Kernel version: not captured in the published extracts.
- Workload: 8 private prompts (3 prose, 3 code, 2 agent) × 256 tokens, B1.
- Order: a1 b1 c1 d1 d2 c2 b2 a2 e2 e3 d3 c3 b3 a3; fresh engine per arm.

## Verdict
- The prediction held: +50.6 % from a to e, inside the predicted range. The split's abort line fired: its windows were 47 % longer, so the split is not the decode layout.

## Reproduce
- Flash Next harness (build, MTP, arms) on the fork's engine. About 30 GPU-min including a third e rep.
