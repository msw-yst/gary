# FG-07: Two exact decode fusions on build 11: hyper-connection post inside the all-reduce (AR_POST), merged attention launches (ATTN_MERGE)
Status: kept (part of build 12) · Date: 2026-11-11
Code: in Gary's release commit. Flags: `DS4_AR_POST=1|3`, `DS4_ATTN_MERGE=1|2` (both default off); `DS4_ATTN_MERGE=3` from build 16 (addendum).

## What and why
- HX-20 measured about 2.7 µs for each extra dependent kernel on the lead's path, and about 1,463 kernels a token on the lead. This card tests whether removing launches on that path pays at that price.
- `DS4_AR_POST` folds the hyper-connection post step (bit 1) and the put of the partial sum (bit 2) into the all-reduce's sum kernel. With both bits (`=3`) that is −2 launches an all-reduce, −160 a token on every card.
- `DS4_ATTN_MERGE` runs five small, independent attention-side kernels (q norm, the window ring copies, the KV row finish, q RoPE) as two launches: −3 a layer, −120 a token on every card. `=2` also covers multi-row windows (verify, batch).
- Target slice: the launch gaps on the critical path, about 1,180 of the lead's 1,463 launches a token [I] (the lead's own experts between publish and join are hidden behind the helpers; ANATOMY §1.5).

## Prediction

| AP1 (`AR_POST=1`) | −80 | −0.20 to −0.35 | slower than off |
| AP3 (`AR_POST=3`) | −160 | −0.40 to −0.70 | count down but gain < 0.1 ms |
| AM1 (`ATTN_MERGE=1`) | −120 | −0.30 to −0.70 | count down but gain < 0.1 ms |

- Pre-registered: yes, in the run script header and a design note committed before the run.
- Noise rule: a gap no larger than the larger rep spread is "not separable from noise".

## Correctness
- Both flags are bit-identical by construction: no reduction order changes, the folded code is the same statements on the same values, and no buffer is added (so the VRAM expert placement is unchanged; see QA-08 for why that matters).
- Load-time checks compare old and new launches byte for byte on every XTX, at 1 and 16 rows, with guard bytes. All passed (MEASURED).
- End to end: every arm IDENTICAL to off on plain decode, drafter decode (greedy) and batch-test B 1/2/8; off IDENTICAL to build 11 (MEASURED).
- One part is covered only end to end, not at load: the cross-card flag protocol of bit 2.

## Timing
- Hardware: 4 × RX 7900 XTX (XTX #1–3 Gen4 x16, XTX #4 Gen4 x8) + 4 × MI50 32 GB at 135 W (Gen4 x4 each). XTX at minimum power cap with −50 mV. MI50 DPM `high` (CP-03).
- Software: ROCm 7.14 on Linux; Strata v0.2.9 plus Gary's changes (build 11 plus these flags).
- B1: plain decode, 64-token prompt, 256 tokens, drafter off, 3 interleaved reps an arm. Drafter-on pair: confidence 0.4, block 3, greedy, 3 reps.

## Verdict
- **ATTN_MERGE held its prediction**: −0.46 ms for 120 fewer launches, about 3.8 µs a launch, a little above HX-20's 2.7 µs because the merged kernels' own short durations go too.
- **AR_POST missed.** Bit 1 alone made the token 0.06 ms *slower*, which is its pre-registered disproof: the five-block sum kernel's extra post-step tail costs more than the launch it saves. Both bits together saved 0.20 ms, under the −0.40 to −0.70 predicted: about 1.3 µs a launch, because the fused all-reduce kernel gives part of the saving back.
- **Together: −0.667 ms (−4.6 %)**, just under the predicted −0.70 to −1.40. Exact, kept, and part of build 12 (SV-09).
- The launch counts came out exactly as predicted, so the miss is in the price per launch on the all-reduce path, not in which launches were removed.

- Short context only. The timings carry the drafter-off seeding cost (about 0.2–0.3 ms; see SV-09) on both sides.
