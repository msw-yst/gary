# NX-15: Shared pool at one user per worker, with and without MTP
Status: finding · Date: 2026-11-21
Code: as NX-14. Flags: MTP arm adds `STRATA_BATCH_MTP=1` on every server (pool hot prefix 4,300, MI50 caches 5,100).

## What and why
- NX-14 measured 4-16 users. Agents often run one or two at a time, and MTP roughly doubles one user's speed on one card.

## Prediction
- No numeric prediction was recorded before the run.
- Pre-registered: no.

## Correctness
- MTP off: reference hash on both workers; worker 1 == worker 2 3/3 on the speed prompts (baseline 1/3) (MEASURED).
- MTP on: reference `a7ae6623797f17fe` on both workers; batched == solo 4/4 and 8/8 on each worker, alone and loaded; loaded == alone 8/8; worker 1 == worker 2 8/8. The texts equal the MTP-off pool's: **in the pool, MTP changes no bit of the output** (MEASURED).

## Timing
- Hardware: 2 × RX 7900 XTX 24 GB, 4 × Instinct MI50 16 GB (135 W cap), EPYC 7642 (48 cores), 256 GB DDR4-2666.
- Software: Strata v0.2.9 plus this fork's changes on ROCm 7.2 (the runtime in Strata's ROCm image). Kernel version: not captured in the published extracts.
- Workload: one user on worker 1 with worker 2 idle (3 prompts in turn), the same on worker 2, then one user on each; 384 tokens, temperature 0. MTP off: one trial each. MTP on: alternating P B P B, two trials each.

## Results
| 1 user | MTP off: pool / baseline | ratio | MTP on: pool / baseline | ratio | label |
|---|---|---|---|---|---|
| on worker 1, the other idle | 54.35 / 51.48 | 1.056 | 86.52 / 78.21 | **1.106** | MEASURED |
| on worker 2, the other idle | 53.59 / 50.31 | 1.065 | 86.95 / 74.42 | **1.168** | MEASURED |
| one on each, per user | 52.26 / 47.48 | 1.101 | 83.13 / 72.47 | **1.147** | MEASURED |
| one on each, aggregate | 104.5 / 95.0 | 1.100 | 166.3 / 145.0 | 1.147 | MEASURED |

MTP's own gain at 1 user on worker 1: pool 1.59x, baseline 1.52x. Drafts accepted ~90 % on these prompts. A user beside the other worker's user loses 3.6 % on the pool and 7.8 % on the baseline (whose CPU paths share DRAM) (MEASURED).

## Verdict
- The pool is faster at one user too, and more so with MTP: 83-87 tok/s per user for one or two users. MTP on the pool at more than one user per worker is not measured yet.

## Reproduce
- "Layout 3" in [README.md](../README.md#launch), with and without `STRATA_NO_MTP=1` / `STRATA_BATCH_MTP=1`.

## Notes / caveats
- **Runtime control:** every pool cell (MTP off and on) ran an engine build with the ROCm 7.2.1 HSA runtime swapped in; every baseline cell ran the build with its bundled runtime. With MTP off a control put the baseline on the pool's own build and runtime: pool vs that baseline 1.098x per agent at 4 users (39.96 vs 36.38) and 1.181x at 8 (28.64 vs 24.25), and the two baselines are within 0.985-1.003 of each other, so the runtime does not explain the gain ([data](../data/2026-11-21-dp-pool.md) section 7) [MEASURED]. The MTP-on ratios on this card have no same-runtime control.
- Open: an earlier one-card MTP arm on an older engine and environment gave a different reference text (`da29bc7d5a0ba433`); with today's standard environment both arms give the no-MTP reference. Not re-baselined.
- Absolute numbers come from a private prompt set (8 prompts, not published); ratios between arms of the same run are the comparable quantity.

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output), ESTIMATE (our arithmetic) or INFERRED (our own reading).

Sources: [data/2026-11-21-dp-pool.md](../data/2026-11-21-dp-pool.md) sections 5 and 6.
