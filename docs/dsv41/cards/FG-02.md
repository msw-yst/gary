# FG-02: Decode kernel fusions: HC_FUSE, ROUTE_FUSE, DECODE_TRIM, ROUTER_BF16
Status: kept (via build 10) · Date: 2026-11-09
Code: in Gary's release commit (ported from a community MIT project; credited in NOTICE). Flags: `DS4_HC_FUSE=2 DS4_ROUTE_FUSE=2 DS4_DECODE_TRIM=7 DS4_ROUTER_BF16=1` (build-10 deploy env).

## What and why
- Fuse the per-token HC mix / split / norm / int8 rounding into one launch; do the router stage in two launches; trim quantise and copy launches; keep BF16 router weights in BF16 on the GPU.

## Prediction
- Design note: +4–8 % decode for the three fusions together (estimate).
- Pre-registered: yes (design note).
- Every fusion flag-on run must match flags-off byte for byte, except ROUTER_BF16 without its memory pad (it moves experts).

## Correctness
- Solo, drafted, B8 and logits dumps: each fusion and all together IDENTICAL to off (MEASURED).
- ROUTER_BF16 without the pad: DIFFER (it frees 150 MiB per member, which changes expert placement) (MEASURED).
- ROUTER_BF16 teacher-forced (tp3h3 vs a single-group reference): 96.10 % vs 95.84 % top-1; paired 95 % interval of the difference [−0.24, +0.74] pp includes 0 (MEASURED).

## Timing
- Hardware: 4 × RX 7900 XTX (XTX #1–3 Gen4 x16, XTX #4 Gen4 x8) + 4 × MI50 32 GB at 135 W (Gen4 x4 each). XTX at minimum power cap with −50 mV. MI50 DPM `auto`.
- Software: ROCm 7.14 on Linux; Strata v0.2.9 plus Gary's changes. Kernel version: not captured in the published extracts.
- One rep, not an isolated A/B (REPORTED). Built-in load-time checks of each fusion's kernels ran on every flag-on start (MEASURED).
