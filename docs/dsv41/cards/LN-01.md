# LN-01: Which experts the CPU lane computes: not a cold tail, placed by a poor ranking; and the bench text loops
Status: finding (led to LN-03 and LN-04; its placement prices measure a looping bench text) · Date: 2026-11-21
Code: not in the fork's release commit (internal build `lanehist-r1`, commit e6e0bcae). Flags: `DS4_EXPERT_HIST`, `DS4_LANESPLIT=2` (stamps inside the lane's expert calls) (measurement only, default off).

## What and why
- The CPU lane computes the experts no GPU holds. Is it serving a cold tail (rare experts, nothing to gain) or mid-hot experts misplaced by the placement ranking? How much would better placement save, and where is the lane's fixed cost per call?

## Prediction
- Desk study prices: option 5 (+420 MI50 and +100 XTX expert slots) 0.64 ms a token; option 3 (one more MI50) 1.82 ms (INFERRED). Pre-registered: yes.

## Correctness
- Timing with instruments on vs off: 21.465 vs 21.627 ms a token, 0 tokens flagged (MEASURED). The exactness and eviction checks were NO DATA (the eviction reader was broken; fixed for LN-03).

## Timing
- 21 Nov, the test machine (four XTX + five MI50 helpers), a measurement build on the native MXFP4 pack, fixed placement, single user, drafter off, greedy, 2K prompt, 4,000 tokens, untraced.

## Verdict
- **The lane computes mid-hot experts because the static profile is a poor predictor of live picks.** Better placement data at the same VRAM looked worth ~1.5 ms a token; the desk study underpriced options 3 and 5 by 1.5–4×.
- The fixed per-call cost is mostly gate/up thread imbalance, fixable in the kernel (tried in LN-03).
- **Later finding (21 Nov):** this bench's greedy decode enters a 23-token loop at token 549 (126 distinct token ids in 4,000; 22 in tokens 1,000–4,000) (REPORTED). The "not a cold tail" reading and the ~1.5 ms price therefore describe that loop's experts; any result sensitive to the expert distribution on this bench is suspect. Offline, counts help only on the same workload: lane share 0.0065 for served counts on served text, but 0.19 for bench counts on served text (REPORTED).
