# NX-22: How many agents get 40 tok/s on the pool: 4 steady, 2 on agent turns
Status: finding · Date: 2026-11-22
Code: the best-known pool configuration (needs the switches of [NX-19](NX-19.md) and [NX-20](NX-20.md)); prompt cache options as in Strata.

## What and why
- [AGENT-TURNS.md](../AGENT-TURNS.md) set the goal for thinking-on coding agents: at least 40 tok/s of sustained decode per agent and TTFT at most 30 s at p95. On the best-known configuration, how many concurrent agents meet both, on a steady short-prompt load and on agent turns with long contexts?
- Configuration: the pool on hugetlbfs, 8 slots per worker, `STRATA_BATCH_MTP=1 STRATA_BATCH_MTP_ADAPT=4` (hot 3,150 / MI50 5,400), MI50s pinned at DPM high, the reseated link (NX-18).

## Prediction
- Pre-registered: yes, with the headline rule fixed in advance: the largest number of agents at which, in both trials, every agent is >= 40 tok/s and the TTFT p95 is <= 30 s (agent turns: over warm turns).
- Estimates: steady 4; agent turns with the prompt cache 2; without it 0, at most 2 (ESTIMATE).

## Correctness
- Gates passed with the prompt cache on and off: reference text on both workers, batched == solo, loaded == alone, worker 1 == worker 2 (short prompts). Steady texts identical across trials (MEASURED).
- **Agent turns were not identical from run to run under concurrency**: 73 of 96 turns at 16 agents (32/48 at 8). See [NX-23](NX-23.md) and [NX-24](NX-24.md) for the causes and fixes (MEASURED).

## Timing
- Hardware: 2 × RX 7900 XTX 24 GB (272 W cap), 4 × Instinct MI50 16 GB (135 W cap), EPYC 7642 (48 cores), 256 GB DDR4-2666.
- Steady workload: 8 prompts × 384 tokens, thinking off, temperature 0; 1 to 8+8 users.
- Agent-turn workload: one 6-turn session per agent built from this repository's sources (system prompt, 4 tools, a coding task, `read_file` results); contexts p50 12.8-16.9k tokens, max 32.3k; thinking on, temperature 0, max_tokens 1,024; 2, 4, 8, 16 agents split over the two workers; prompt cache on (`prompt-cache=6`, `conversation-cache-mib=8192`, `conversation-cache-slots=8` per worker) or off. 2 trials per level.

## Verdict
- **Headline: 4 agents on the steady load, 2 agents on agent turns.**
- Once the prompt cache is on, agent turns fail on each agent's decode rate, not on TTFT (warm p95 at most ~22 s up to 16 agents; cold first turns 54-79 s at 8-16 agents, inside the 60-120 s AGENT-TURNS allows for a cold full context).
- **The limit is prompt reading on the XTX.** Each worker reads its prompts on its own XTX; no MI50 takes part in a `--batch` prompt read. A read lends half of the XTX's hot expert slots to the prompt path and streams ~23,000 experts (~64 GiB) from host RAM per part, about 2.2 s of every read whatever its length, while the decoding slots run only between a read's parts. In one cell each worker spent 426-443 s of ~700 s reading prompts. Per agent on agent turns is 0.71x the steady rate at 4 agents, 0.50x at 16 (MEASURED; the stream share ESTIMATE).
- Above 4 agents decode itself is the limit: the steady 4+4 is 32 tok/s per agent with no prompt reads at all.
- **Serve agents with the prompt cache on.** With it off, every re-send (the hand-off into a batch slot, the thinking-budget wrap-up) reads the whole 8-32k context again: 1.8x lower per-agent decode at 4 agents (21.4 vs 38.7), warm TTFT p95 26 s against 6 s, and clients stalled past 30 s at 8 and 16 agents. Its cost on the pool: ~14 GiB of host RAM at 16 agents, parks of 140-200 ms, ~20 ms of KFD eviction per park.

## Reproduce
- "Layout 3" in [README.md](../README.md#launch) with the best-known settings listed there; any agent harness that resends the conversation each turn, prompt cache on.

## Notes / caveats
- Our turns are short next to AGENT-TURNS' (output p50 148-281 tokens, contexts up to ~32k against p95 50k there), so each agent reads a prompt every 10-30 s. That is the read-heavy, pessimistic side for decode during reads.
- None of the temperature-0 speed-prompt outputs loops (checked at 384 and 1,024 tokens), so looping does not inflate these numbers.
- Next steps (not built): prompt reads on the MI50s ([NX-25](NX-25.md), ESTIMATE: headline 2 -> 4 on agent turns), or a third XTX (ESTIMATE: ~3 on agent turns, ~6 steady).
- The session generator and client are not published yet; the 8-prompt steady set is private.

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output), ESTIMATE (our arithmetic) or INFERRED (our own reading).
