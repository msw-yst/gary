# SV-10: Builds 13 and 13s: four exact features merged, then concurrent serving; batched output and the prompt helper
Status: kept (build 13s is the served configuration measured in SV-11; build 15 follows it, SV-14) · Date: 2026-11-13
Code: in Gary's release commit. Build 13 = build 12pf + `DS4_EG_AHEAD` (FG-09) + `DS4_TOPK_MB` (FG-10) + `DS4_G906_SGNLDS` (HX-24, in the code, off when served). Build 13s = build 13 + concurrent serving (DR-07). Served environment from 13s: `DS4_EG_AHEAD=1 DS4_TOPK_MB=1 DS4_PF_HELPER=8192 --mmap-experts on` (EB-08, PF-11), `DS4_BATCH_DSPARK_SAMPLED=1`, `DS4_BATCH_DSPARK_MAX=3`, PAR 4.

## What and why
- Each feature had passed its own A/B on its own build. The merge had to show no interaction, and the concurrent build had to keep each request's output what it would be alone.
- Two further questions came up and were answered here: does one served process carrying 4 banks slow down a single user (the "bank tax"), and why did batched greedy output differ from solo greedy output on build 13s?

## Prediction
- Every identity comparison byte-identical; batched greedy == solo greedy (it was on the concurrency build before the merge, 8 of 8); no bank tax (+0.1 to +1.0 %). Pre-registered: yes, in each run's script.

## Correctness
- **Build 13 merge: 14 of 14 identity lines IDENTICAL** — flags unset vs build 12pf; each feature on vs its own single-feature build (decode, drafter decode, batch test, and 32K / 110K for the top-k); all on vs all off (MEASURED).
- **Build 13s, one user:** served greedy output IDENTICAL to build 12pf and to build 13, flags unset and with the deploy flags (MEASURED).
- **Build 13s, 3 users, prompt helper on: batched greedy ≠ solo greedy (5 of 8 prompts identical).** Solo repeats stay identical (8 of 8), and the sampled distribution test passes. The cause was found by switching one piece off at a time:

| arm | batched = solo (of 8) | label | data |
|---|---|---|---|
| everything on | 5 (differ: prompts 1, 2, 4) | MEASURED | identity-concurrency-banks.txt |
| memory-mapped experts off | 5 (the same three) | MEASURED | identity-concurrency-banks.txt |
| Engram ahead off | 5 (the same three) | MEASURED | identity-concurrency-banks.txt |
| **prompt helper off** | **8** | MEASURED | identity-concurrency-banks.txt |

- **The MI50 prompt helper is the sole cause.** It is not bit-identical (PF-11), and its sums depend on how a prompt is chunked; under concurrency a new prompt is read interleaved with other banks' decode in different chunks, so its state differs slightly and greedy near-ties flip [I]. The diverging outputs keep the same reasoning and differ in wording at a near-tie (for example "The input lists are assumed to be sorted" against "Assumes each input list is sorted").
- Repeated on build 13s the next night: helper on, the same 5 of 8; helper off, 8 of 8 and the full identity set passed (MEASURED).

## Verdict
- **The merge is exact and concurrency is free for a single user.** Build 13's features do not interact; carrying 4 banks costs one user nothing measurable. An earlier +13.7 % "bank tax" was two different output trajectories, not banks.
- **With the prompt helper on, each request is deterministic only when it runs alone.** Batched and solo greedy outputs can differ at near-ties. With the helper off, build 13s is bit-exact including batched. The served configuration keeps the helper on for its time-to-first-token gain (SV-11); whether the difference matters is a task-level quality question (QA-05).
