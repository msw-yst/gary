# SV-19: The 2.25-bit pack, first setup against now: decode 56 → 73 tok/s and a 2K prompt about 3× faster in the CLI; served equal to release 3 except one 32K regression, since explained
Status: finding · Date: 2026-11-20
Code: the first setup is the 9 Nov four-XTX build with no flags (our like-for-like anchor); "now" is the current internal engine with five helpers and the switches that apply to the 2.25-bit pack; the middle arm is release 3's deployment (build 17).

## What and why
- Most of the work since 16 Nov targeted the native pack. This run asks what the whole project has bought the 2.25-bit pack, the one in the public releases: the first four-XTX setup against today, in the CLI (no drafter), and served against the release-3 deployment.

## Verdict
- **The 2.25-bit pack's gains came between 9 and 17 Nov** (decode × 1.30, a 2K prompt about 3× faster in the CLI). The native pack's prompt work since then does nothing for it, because the 2.25-bit pack already has every expert on a GPU.
- **Served, now equals release 3**, except the 32K first token. That regression is one switch built for the native pack, `DS4_STORE_UNHELD`; with it off the current build reads 32K in 17.8 s (PF-22).

## Open
- **The release-3 deployment's one-user decode was 6–8 % slower than on 16 Nov** (2K 8.54 against 8.08 ms, 8K 9.25 against 8.53), with four users, eight users and first tokens reproduced. What we know (MEASURED unless marked):
  - Hiding the newly fitted fifth MI50 from the engine changed nothing (× 0.997), so the first explanation, that the visible card moved an expert, is withdrawn.
  - About 95 2.25-bit run logs since 15 Nov split by boot: one XTX's power cap was 272 W on every boot but one, where a 294 W cap had been applied by hand (a boot-time setting otherwise puts each XTX at its firmware minimum). On the 294 W boot the leads placed one expert more (6,827 against 6,826). Why a power cap moves 2 MiB of free VRAM is not known: this is a correlation, not a mechanism.
  - That one-expert shift changes which requests keep their drafts; without the 2–3 affected requests the per-step difference is 1–2 % or less (INFERRED from per-request timing).
  - A power-cap A/B to settle it was not run: a benchmark nuance, not a property of the engine.
- Lesson for cross-day comparisons: with sampled drafting, one user's decode depends on the token stream; three reps of three requests do not average that out.
