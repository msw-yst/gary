# TP-10: Tensor-parallel 3 with the fourth XTX as a helper: not testable on the native build, its 129,280-row output head does not split three ways
Status: dropped (the route is closed; an XTX helper only with a fifth card) · Date: 2026-11-19
Code: no new code. Command-line layout only (`--tp 3 --helper-device …`), on the internal native build.

## What and why
- On native, decode waits for the CPU lane and the MI50 joins (FG-21, FG-22). One idea: run the trunk on three XTX (tensor-parallel 3) and use the fourth XTX as a fifth helper, which holds more experts than an MI50 and computes them faster.

## Prediction
- Pre-registered: at least 3 % lower one-user 2K decode time for tp3 + XTX helper against tp4; the plan itself predicted no gain.

## Correctness
- Not reached.

## Timing
- 19 Nov, the test machine: 4 × RX 7900 XTX + 4 × MI50 helpers; native MXFP4 pack, internal native build. Arms: tp4 + 4 MI50 (production), tp3 + 4 MI50 + the fourth XTX as a helper, the same with the drafter off tensor parallel, tp4 again.

## Results
| arm | result | label |
|---|---|---|
| tp4 (production) | served cleanly: 2K 11.35 ms a token (88.1 tok/s), 16K 10.80 ms; first token 2K / 8K / 16K 16.9 / 18.8 / 29.4 s | MEASURED |
| tp3 + XTX helper | **never served**: the engine stops at load because the 129,280-row output head does not divide over 3 members ("outputs do not split") | MEASURED |
| the other two arms | skipped (no blind retry) | — |

## Verdict
- **Not testable on the production native engine:** tp3 needs the head split to handle a vocabulary that 3 does not divide (an engine change), and the XTX-helper path was never reached.
- The tp3 route is dropped. An XTX helper is worth testing only as a fifth card beside tp4.
- Earlier tp3 runs (TP-01, TP-05) loaded on earlier builds; why the native build refuses where those did not was not examined here.

## Reproduce
- Start the native build with `--tp 3` and read the load error.
