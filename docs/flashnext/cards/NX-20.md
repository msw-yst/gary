# NX-20: Adaptive MTP: no drafter work above N live slots
Status: kept (opt-in; we run N = 4 on the 8-slot pool) · Date: 2026-11-22
Code: opt-in, off by default ([Settings](../README.md#settings)). Flags: `STRATA_BATCH_MTP_ADAPT=N` with `STRATA_BATCH_MTP=1`; `STRATA_BATCH_MTP_ADAPT_HEAL_DIV` (default 8).

## What and why
- MTP pays up to 4 users per worker and loses at 8 ([NX-17](NX-17.md)). Dropping proposals above 4 live slots still ran every drafter's catch-up, +5.7 ms a window. A fixed policy gets one side wrong whenever the load moves.
- With the switch, a window over more than N live slots carries one row a slot and does no drafter work; each slot's final residual row and token are copied to host memory (~40 KiB a slot). When N or fewer are live again, a slot rebuilds its drafter's missing K/V in one batched pass over the kept rows, then drafts as before. A slot near the end of its request skips the rebuild. The rebuild also runs before a conversation is parked or continued.
- Drafts only choose what the verify window checks; every emitted token is the verifier's, so this cannot change the output.

## Prediction
- Pre-registered: yes. N = 4 at 2+2 and 4+4 >= 0.98x the plain MTP arm, at 8+8 >= 0.98x MTP off; on a 2 -> 8 -> 2 ramp, the long requests' whole rate >= 0.98x the better of the two fixed policies; texts identical.

## Correctness
- Reference text on both workers on every arm; batched == solo, loaded == alone, worker 1 == worker 2 8/8; one distinct text list per level over all 10 cells, and the ramp's texts identical through the transitions and rebuilds (MEASURED, short prompts).
- The park / continue rebuild with the prompt cache on, at 16 agents (decode share 0 to remove timing): MTP on vs off 94/96 turns identical, both differences after a thinking-budget wrap-up re-send; 53-54 rebuilds per worker (MEASURED).

## Timing
- Hardware: 2 × RX 7900 XTX 24 GB (272 W cap), 4 × Instinct MI50 16 GB (135 W cap), EPYC 7642 (48 cores), 256 GB DDR4-2666.
- Workload: pool, 8 slots per worker, hugetlbfs arena; 2+2, 4+4, 8+8 users × 384 tokens and a ramp (2 long requests per worker, 6 short ones joining); arms OFF, W8 (plain MTP), A4, A2, OFFh (MTP off at MTP's cache sizes), alternated, 2 trials.

Engine lines: above N, keeping the rows costs 0.03-0.04 ms a window (8+8 at 47.1-47.8 ms a window against MTP off's 46.8); a rebuild 0.070 ms a cell (~27 ms for a 383-cell hole); 87-88 % of proposals accepted after rebuilds (MEASURED).

## Verdict
- Kept: every bar met. One configuration runs at plain MTP's speed at 4 or fewer live slots per worker, at MTP off's speed above, and 10 % faster than either on a load that moves between them.
- N = 4: at 4+4 ADAPT=2 runs at MTP off's speed while ADAPT=4 keeps MTP's +4-5 %.
- What ADAPT loses to MTP off at 8+8 (~1 %) is the drafters' VRAM (550 fewer hot experts), not drafter work.

## Reproduce
- "Layout 3" in [README.md](../README.md#launch) at 8 slots per worker with `STRATA_BATCH_MTP=1 STRATA_BATCH_MTP_ADAPT=4` and the MTP cache sizes (hot 3,150 / MI50 5,400).

## Notes / caveats
- Holes longer than ~770 cells were not measured (the cap that forces an immediate rebuild, 4,096 cells, was not reached).
- Absolute numbers come from a private prompt set (8 prompts, not published); ratios between arms of the same run are the comparable quantity.

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output), ESTIMATE (our arithmetic) or INFERRED (our own reading).
