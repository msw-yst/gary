# FG-17: Decode phase timings without a tracer: real kernel gaps of 2.9 µs, and the MI50s on the critical path
Status: finding (measured on a later build; the phase-timer build is not in this release) · Date: 2026-11-14
Code: not in the fork's release commit (a later build). Flags: `DS4_PHASE_TIMES=1` (measurement only; default off, never served); otherwise build 15's flags as deployed.

## What and why
- FG-15's kernel trace split a one-row decode step into stages, but a tracer inflates time (× 2.26 on the whole step), so its milliseconds were rescaled shares, and FG-16 then guessed that most of the traced inter-kernel gap was the tracer itself.
- This build writes GPU timestamps from inside the engine's own kernels at fixed points of every layer (the lead XTX, each member XTX and each MI50 helper window), reads them back every 256 tokens after a step's sync, and prints per-phase medians at exit. It measures the same split, the real gap between dependent kernels, and which side of the MI50 join finishes last, with no tracer.
- Arms: one-row decode (64-token prompt, drafter off, 256 tokens), the batch test at B = 1, 2, 4, 8, drafter on, and three B1 overhead pairs (same binary, flag on against unset). Four production MI50 helpers.

## Prediction
- Per-phase B1 times on the lead (pre-registered, before the run): attention 5.36 ms (4.60–6.00), attention all-reduce 0.85 (0.40–1.30), router + publish 1.50 (1.00–2.00), publish → join 2.60 (2.00–3.20), join + combine 1.00 (0.60–1.50), MoE all-reduce 0.57 (0.30–1.00), token tail 0.74 (0.40–1.40), step 12.62 (12.20–13.20).
- Real inter-kernel gap 0.5 µs (0.1–1.5), from FG-16's desk reading; the helper finishes after the lead reaches its join in 55 % of pick layers (35–75 %); overhead < 1 % (central 0.4 %); the stamped step within 3 % of the engine's own ms a token.

## Correctness
- Flag on against unset: stdout IDENTICAL token for token at B1 (three pairs), in the batch test (solo references and batched sequences, B 1, 2, 4, 8) and with the drafter on; the same expert placement each pair (MEASURED, phase-times.txt).

## Timing
- 14 Nov 07:45, after the hardware change (HW-09): 4 × RX 7900 XTX + 4 × MI50 at 135 W, DPM `high`. A served arm was planned; the server did not start (the launcher refused one of the run's environment settings), so there is no served data.
- Device clocks were calibrated against the host three times per device (fit within 3.1 ppm of nominal).

## Verdict
- **OK WITH CAVEAT** (the run's own verdict): every phase landed in its band and the stamps close on the engine's own step to 1.05 %; the overhead, 1.23 %, was over the 1 % line and under 2 %.
- **The real kernel gap is about 2.9 µs, not 0.1–1.1 µs.** The trace's 3.6–3.8 µs was only mildly inflated, so with ~1,070 kernels a token on the lead about 3.1 ms of a 13 ms step is gap time [I]. Fewer launches (fusion, graph-style launch) have a ceiling of about 3 ms a token; FG-16's "mostly a tracer artefact" reading is withdrawn there.
- **At one row the MI50 helpers are on the critical path in 98 % of layers,** not about half. The helper chain is ~71 µs a pick window, so every µs off it is worth about 40 µs a token [I]. With 2–4 rows the lead's own work grows and the helper finishes last in only 26–37 % of layers.

## Notes / caveats
- The batch-test B8 overhead pair read −11.8 % (flag on faster): B8 steps vary between runs (FG-15 notes the same), so only the B1 pairs are used for the overhead figure.
- In the batch test the all-reduce boundary gap reads 6.6–8.4 µs instead of 2.9 µs (the combine and MoE boundaries stay at 3.0–3.5 µs); why is not examined here. The one-row figures are the ones used above.
- The ~3.1 ms of gap time is a product of a launch count (FG-15's trace) and a median gap (this card); it is an estimate, not a measured total [I].
