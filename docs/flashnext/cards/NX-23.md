# NX-23: Lent experts never on the CPU during prompt reads; the concurrent read on the pool
Status: kept (opt-in; `STRATA_BATCH_LENT_EXACT=1` recommended on the pool) · Date: 2026-11-22
Code: `STRATA_BATCH_LENT_EXACT` (opt-in, [Settings](../README.md#settings)); `STRATA_BATCH_CONCURRENT_READ=2` and `STRATA_BATCH_LENT_GPU=1` as in [NX-11](NX-11.md). Flags: `STRATA_BATCH_LENT_EXACT=1` (implies `STRATA_BATCH_LENT_GPU=1`), optionally `STRATA_BATCH_CONCURRENT_READ=2`.

## What and why
- On the pool, agent-turn texts differed between two identical runs: 32/48 turns identical at 8 agents, 73/96 at 16 ([NX-22](NX-22.md)). The short-prompt gates never saw it.
- Cause: with `--batch` a prompt read lends 1,556 of the XTX's hot expert slots to the prompt path and marks those experts missing. A decode window that runs between the read's parts left a missing expert that no MI50 holds to the CPU, which rounds differently from the GPUs. Whether a token's step landed during a read depends on timing. A diagnostic with no decode during reads (`STRATA_BATCH_DECODE_SHARE=0`) gave 47/48.
- The pool runs had not set `STRATA_BATCH_LENT_GPU=1`. `STRATA_BATCH_LENT_EXACT=1` turns it on and makes it a guarantee: at each loan every lent expert is checked for a device alias in the registered arena; if one has none, no window runs until the read gives the slots back; and the engine counts lent experts computed by the CPU, so 0 can be checked.
- Separately: can decode run beside a read (`STRATA_BATCH_CONCURRENT_READ=2`) to lift the agent-turn headline from 2 to 4?

## Prediction
- Pre-registered: yes. Determinism bar: 100 % of turns identical between two runs at 8 and 16 agents, and 0 lent experts on the CPU. Agent turns with the concurrent read: 4 agents meeting the goal ("a coin toss"). Steady load >= 0.98x.

## Correctness
- **0 lent experts on the CPU in every engine log** (for example 99,256 / 85,171 on the GPU); every lent expert had a device alias, so the wait never engaged (MEASURED).
- Run to run: 47/48 at 8 agents and 89/96 at 16 with serial reads; 45/48 at 8 with the concurrent read; every remaining difference starts 24-139 characters after a thinking-budget wrap-up re-send (a second cause, [NX-24](NX-24.md)). Concurrent reads give the same bits as serial reads (MEASURED).
- Gates passed; steady texts identical to the configuration without the switches (MEASURED).

## Timing
- Hardware: 2 × RX 7900 XTX 24 GB (272 W cap), 4 × Instinct MI50 16 GB (135 W cap), EPYC 7642 (48 cores), 256 GB DDR4-2666.
- Workload: NX-22's agent-turn and steady workloads and configuration, prompt cache on, 2 trials per arm.

## Verdict
- `STRATA_BATCH_LENT_EXACT=1`: kept and recommended on the pool. It removes the timing-dependent CPU experts (0 on the CPU) at no measurable speed cost (8 agents 18.4 vs 18.6 per agent; 16 agents 8.3 vs 9.1, within the trial spread). The 100 % bar is not met by it alone; the rest is NX-24's cause.
- `STRATA_BATCH_CONCURRENT_READ=2` on the pool: exact, +7 % per agent at 4 agents and +10 % at 8 (slowest +20 % at 8), warm TTFT +1 s. It does not lift the headline (the slowest agent at 4 stays at 32.3-32.6), and at 16 agents its slower reads stalled a client past 30 s: use it only up to 8 agents per pool.
- Why so little: beside a read the decode windows take ~140 ms instead of ~45 ms and the read slows from ~1,250 to ~800-880 tok/s. The XTX is saturated by the read; concurrency only moves XTX time between the reader and the decoders.

## Reproduce
- "Layout 3" in [README.md](../README.md#launch) with `STRATA_BATCH_LENT_EXACT=1`; the engine logs "0 of 1556 lent experts have no device alias" and, per request, "N lent experts computed by the GPU so far, M by the CPU" (M must be 0).

## Notes / caveats
- One-card servers ([NX-11](NX-11.md)) measured lent experts on the GPU with `STRATA_BATCH_LENT_GPU=1` alone (16/16 == alone); the pool runs before this card did not set it.
- Absolute numbers come from our own agent sessions and a private prompt set; ratios between arms of the same run are the comparable quantity.

Numbers are labelled MEASURED (read from a raw run file or a script-written summary), REPORTED (from a commit message or write-up at the time, not re-checked against raw output), ESTIMATE (our arithmetic) or INFERRED (our own reading).
