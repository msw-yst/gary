# AR-11: A direct reduce-scatter + all-gather for prompt all-reduces: bit-identical, exchange time × 0.62, first token −2 to −3 %
Status: kept (a release candidate; internal branch, not yet in a release) · Date: 2026-11-18 (passed 2026-11-19)
Code: not in the release commit of Gary, our fork of Strata (internal branch only). The prompt all-reduce over P2P as a reduce-scatter plus all-gather into uncached receive slots, one destination a step, checksummed flags, member-order rounding (bit-identical to the host route by construction).

## What and why
- AR-10 showed direct P2P cannot beat the host route at decode sizes, but the same benches showed it winning at prompt sizes. Prompt chunks all-reduce megabytes a call, twice a layer.
- The engine's existing prompt all-reduce by peer stores (AR-04) moves the whole message to every card. A reduce-scatter plus all-gather moves each byte once each way.

## Prediction
- Served, pre-registered for the final run: the exchange stage × 0.60–0.72; first token −0.46 s at 8K and −1.2 s at 32K; decode not worse.

## Correctness
- Bench: 0 wrong values, 0 stuck in every run, including a soak of 1,000,000 calls at 256 KiB, 50,000 at 4 MiB and 20,000 at 16 MiB, every call checked on the device, with restarts (MEASURED).
- The first served port was **not** bit-identical to production on long chunked prompts (5 of 6 differ), although the bench was. Cause found: a wait that silently gave up after 2 s and went on with partial data. Fixed by waiting without that bound; then served frozen-placement identity IDENTICAL, 4,800 traced calls with none different, and no wait over 2 s (MEASURED).
- Final version: bench 15 shapes and a served-sequence replay IDENTICAL, error words 0; served identity IDENTICAL on long and short prompts, placement equal; the 2 s give-up never fired (MEASURED).

## Timing
- 18–19 Nov, the test machine: 4 × RX 7900 XTX (tensor-parallel 4) + 4 × MI50 helpers; native MXFP4 pack, internal native build. Bench at 80 KiB–160 MiB; served at 8K, 16K and 32K prompts, n = 24 a cell in the final run (sized from the served-noise pilot, ME-14).

## Verdict
- **PASS on every gate, inside every predicted band.** The prompt all-reduce's stage time falls by 38 %, the first token by 2–3 % at 8K–32K, output identical. It is the release-4 P2P item, waiting for the release.
- The crossover against the host route is between 80 and 256 KiB, above decode sizes, which is why decode keeps the host route (AR-10).
- The defect is worth remembering: a bench that is bit-exact does not prove the served path is; the served long-prompt identity check found a timeout path the bench never took.

## Reproduce
- No published run: the code is on an internal branch.

## Notes / caveats
- Measured on the native pack, whose prompt reads were 15–20 s at the time; on today's faster prompt path (PF-20) the exchange is a larger share and the relative gain should grow (INFERRED, not measured).
- FP16 variants of the exchange were benched but not ported.
