# HX-36: The MI50 flat MXFP4 kernel served on the native pack (`DS4_MXW=3`): bit-identical, one user −4 %, four users +3.5 %
Status: kept (on in the internal native build; not in a release) · Date: 2026-11-18
Code: not in the release commit of Gary, our fork of Strata (internal branch only). Flags: `DS4_MXW=3` (branch-only, default off). Release 4's code does not contain it.

## What and why
- HX-35 made the MI50's MXFP4 expert kernel 20–34 % faster on served-shape windows, bit-exact. The question here: does that show up in served native decode?

## Prediction
- First served run (`DS4_MXW=1`): verify step at least 0.4 ms faster. Second run (`=3`, the X1 kernel): one-user 2K decode × 0.955–0.975, from 52–60 µs saved a window on about 37 MI50-bound layers.

## Correctness
- First run: its pre-registered gate said BITS FAIL, because the gate also required each arm's second repeat to equal its first, which the server did not do (ME-13). Read after the fact (not the gate): all 6 answers byte-identical between switch off and on, repeat by repeat (MEASURED).
- Second run, corrected gate: BITS PASS, 6 of 6 across arms (MEASURED).

## Timing
- 18 Nov, the test machine: 4 × RX 7900 XTX (tensor-parallel 4) + 4 × MI50 helpers; native MXFP4 pack, internal native build. Second run: no sampler beside the arms, page cache dropped and the same warm-up per arm, ABBA order.

## Verdict
- **Kept for the native build: GO.** One user −4 %, four users +3.5 %, outputs identical. The internal native default now carries it.
- **Not in release 4:** the release candidate does not contain this switch; it should be carried when the candidate is next updated.
- The first run's "no gain" was noise: page-cache state and a sampler on the lane thread's core (ME-15) moved arms by 2–5 %, more than the kernel's effect. The clean second run found it.
- The same walk for the 2-bit MI50 kernels (`DS4_G906_FLAT`) was not served (predicted under 1 % on the 2.25-bit pack).
