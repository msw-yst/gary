# PF-20: DMA straight from the RAM store: a native 2K prompt's first token 15.2 → 3.3 s; the read-ahead skip alone is mixed
Status: kept (GO for the direct DMA; internal native build, not in a release); the read-ahead skip alone: not adopted (worse or mixed) · Date: 2026-11-19 (addendum 2026-11-20)
Code: not in the release commit of Gary, our fork of Strata (internal branch only). Flags: `DS4_STORE_DIRECT=1` (branch-only, default off), on top of PF-19's switches.

## What and why
- After PF-19 a native 2K prompt read took about 4.75 s, and about 3.1 s of it was the host copying each streamed expert from its RAM-store slot into a staging buffer, after which the GPU's DMA read it again. Each expert crossed host memory twice, on four XTXs at once.
- `DS4_STORE_DIRECT=1` registers the RAM store's memory for the GPUs at load, and DMAs each streamed expert straight from its store slot into the XTX: gate and up rows in one DMA each, the down part gathered from the slot by a small kernel, the same bytes the staging path delivers. A slot is pinned while its DMA is in flight, so the store cannot evict or refill it.
- A second arm (Q) asks what PF-19's read-ahead skip does alone, with the helper off as in production.

## Prediction
- Pre-registered (direct against PF-19's best, K): 2K × 0.60–0.90; 8K × 0.65–0.95; 14K × 0.70–0.95; decode × 0.99–1.02; host staging copies × 0.00–0.20.
- GO if at least 80 % of the streamed experts go direct, the host copies fall by at least 60 %, and against K: 2K ≤ 0.85, 8K ≤ 1.00, 14K ≤ 1.00, decode ≤ 1.02, with text closeness passing.
- Q against the baseline: 2K, 8K, 14K × 0.95–1.05 each, decode × 0.98–1.02, disk bytes × 0.30–1.05.

## Correctness
- Every arm CONFIG ok, 0 bad steps, placement frozen. 180 of 180 store chunks registered (MEASURED).
- Direct and staged paths deliver the same bytes by construction (INFERRED from the source). Text closeness, direct against K, 2K: 3 of 3 close (PASS); within-arm repeats 2 of 7 identical (report only; ME-13) (MEASURED).
- The helper is not bit-identical by design (PF-11). A CPU test of the slot pinning passes 19 of 19 (REPORTED).

## Timing
- 19 Nov, the test machine: 4 × RX 7900 XTX (tensor-parallel 4) and 4 × MI50 32 GB helpers at 135 W; one EPYC Zen 2 16-core host, DDR4 at 2933 (HW-13). Native MXFP4 pack. Arms D1 K1 Q1 B1 D2 K2 Q2 B2, each started from a dropped page cache with the same warm-up; cells as PF-19 (three 2K, three 8K, one ~14K read, greedy).

## Verdict
- **Direct DMA: GO.** A native 2K prompt's first token is now 3.33 s against 15.22 s in production (× 0.219), 8K 7.30 s against 16.50 s, 14K 12.6 s against 26.3 s, and decode × 0.895. The host no longer copies experts during a prompt at all.
- The gain shrinks with length (2K × 0.70, 14K × 0.97 against K): once the copy is gone, longer reads are bound by the GPU work and the transfers themselves (INFERRED).
- **The read-ahead skip alone (Q): worse or mixed by its rule.** It cut the disk bytes a 2K read by 54 % and the first token by 16–21 %, but decode was 2.5 % slower (bar ≤ 1.02). Q runs on the new binary, so its ratio mixes the flag with the binary difference. A day earlier, on the older build, the same idea cut storage reads by 30 % without any first-token gain (PF-16).
- This is the end of the chain PF-15 → PF-18 → PF-19 → PF-20: the desk study's estimate for "helper + DMA" was 2K ~2.5–4 s; measured 3.33 s.

## Notes / caveats
- Registering the store's memory for the GPUs (about 221 GB, INFERRED) adds load time; it was not measured separately here.
- One user, greedy, no concurrent prompts; prompts over 14K not tested.

## Addendum (2026-11-20): combined, soaked, and measured as served
- The direct DMA with PF-19's switches and a fifth helper, measured together against production (STACK): first token 2K 15.9 → 2.9 s, 8K 17.3 → 7.1 s, 14K 26.6 → 12.4 s; a 30-minute mixed soak, 254 requests, 0 errors (MEASURED, SV-18).
- As served with a live cache, the 2K first token is about 0.7 s slower than these locked numbers (3.6 s) and decode 6–9 % faster (MEASURED, SV-20, ME-16).
- The read-ahead skip's decode cost seen in arm Q above persisted in a re-run with deterministic placement (formally NO DATA: two arms drifted past 0.97–1.03; paired within the run, one-user decode × 1.019 [1.006–1.032], first token × 0.85), so it was not placement luck alone; in the full setup, where the store holds what the lane needs, it does not appear (MEASURED / INFERRED).
